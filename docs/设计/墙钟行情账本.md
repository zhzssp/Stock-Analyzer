本文回答：大约四个人各自只在自己的电脑上跑助手、没有额外常开主机、麦蕊 licence 只有一份、模型 Key 各人自备时，如何让**最新价按墙钟只查询一次**，并把每一档的副本留下来做回放、时段分析和绘图。

---

## 0. 一句话

四人都是取数员，地位相同。上海时区墙上的每一个档口（先按 5 分钟）最多产生一份现价快照；谁在线谁都可以写这一档，但同一档只许一个真相。这份快照放在**独立的私有 Git 仓库**里：Git 当公共账本和历史胶带，不当行情数据库。产品仓库、本机 SQLite、模型 Key、麦蕊 licence 都不进这个账本。盯盘、表格、问答一律带 `as_of`，禁止各机私自打到的价和时间线上的快照混用。

## 1. 背景与约束

### 1.1 产品形态（不变）

- 助手是本机进程：FastAPI 默认绑 `127.0.0.1`，SQLite + `data/` 在软件根下，不为公网多租户部署。
- 大约四个人使用。每人一台电脑，只跑自己的任务。
- 不把整套服务端部署到云主机，也不另买 NAS / 常开网关机。
- 不下单、不荐股。无源不编数字。演示 licence 不得当成实盘写入任何账本。

### 1.2 钥匙怎么分

| 秘密 | 谁持有 | 进不进 Git |
|---|---|---|
| 麦蕊 `MAIRUI_LICENCE` | 一份套餐，四台 `.env` 都可以有（谁抢到写档谁能打麦蕊）；也可以只放在常开的那几台 | **禁止**进产品仓库和时钟仓库 |
| 大模型 `LLM_API_KEY` | 各人自充、只写在自己电脑的 `.env` | **禁止** |
| `app.db`、决策卡成本、对话 | 各人本机 | **禁止** |
| 档口现价 JSON、各人想看的代码表 | 时钟仓库，四人可读可写 | 要进（这就是账本） |

模型调用永远走各机 `llm.py`，不经过取数员，不经过 Git。

### 1.3 现有代码里的缺口（设计针对什么）

| 现状 | 后果 |
|---|---|
| `MarketClient.quote` / `quotes_many` 每次直连麦蕊，现价没有按墙钟缓存 | 四人各刷一遍就是四份相同 HTTP |
| `list_hs`、日线已有本机 `data/cache` 覆盖写 | 名单和日线不必进 5 分钟总线 |
| 盘中调度约每 5 分钟扫一轮（`src/platform/scheduler.py`） | 若四人都开着盯盘，会四倍打现价；用户还希望以后密到约 1 分钟一档 |
| 启动探测会对样本代码打 `ssjy` | 四台开机各打三枪，与「只查一次」相悖 |
| 启动方式是黑窗口，关窗口即杀进程 | 没人盯屏幕时档口无人写 |
| 产品仓库 `.gitignore` 已忽略整个 `data/` | 本机缓存和数据库本来就不该进源码库；时钟仓库必须另开，克隆放在 `data/clock/` |

额度本身不是瓶颈：普通档量级约每分钟数百次，自选是小池子，`ssjy_more` 一次最多 20 只。问题是**重复劳动**和**盘中横切面不可再造**——麦蕊最新价接口几乎不会把「上周二 10:05 自选并集的那一刀」再卖给你。日线以后还能再拉；5 分钟横切面一旦没落盘就没了。

### 1.4 明确拒绝的做法

| 做法 | 为何不做 |
|---|---|
| 另买一台常开电脑 / NAS 当行情网关 | 没有这笔计算资源 |
| 把工作台绑到 `0.0.0.0` 并带上 licence | 把整套助手和钥匙暴露出去，与「只共享现价」无关 |
| 四台各做 60 秒本地 TTL | 本机变省，麦蕊仍是每分钟四次相同请求 |
| 用网盘同步整份 `data/` | `app.db` 会互相覆盖；licence 可能进同步盘 |
| 在产品仓库提交快照 | 源码 PR、克隆体积、误提交 `.env` 缠在一起 |
| 维护一份大家抢着改的 `latest.json` 或按天追加同一份 JSONL | Git 合并会制造「看起来能合、其实同一档两份真相」 |
| 把日线、财务、股东、成本按 5 分钟提交 | 体积爆炸，且那些数据不是「不可再造的盘中胶带」 |
| 指定唯一取数员、别人永远只读 | 那人关机则整条线停；与「四人都是取数员」不符 |

「一起贡献」不是四人同时各打一遍麦蕊再拼起来，而是：**同一条时间线上每一档只产生一份快照，四人都有资格当这一档的写入者。** 10:05 是 A 写的，10:10 若 A 关了，就由当时醒着的 B 来写。贡献体现在档口不断档，以及代码并集让在线人能把别人已登记的票一并拉到。

## 2. 核心模型

### 2.1 两条时间，两种数据集

| 数据集 | 粒度 | 从哪来 | 用来干什么 | 能不能事后再向麦蕊要 |
|---|---|---|---|---|
| **墙钟胶带（本文）** | 先 5 分钟一档的现价横切面 | 档口内至多一次 `quotes_many`，写入时钟仓库 | 现在看价、盯盘、回放「当时我们看到什么」、画时段折线 | **不能。** 这是账本存在的理由 |
| **日线 / 名单 / 财务 / 股东** | 日或更慢 | 麦蕊 + 本机 `data/cache` | 底/顶/离底、复盘次日 K 线、查询表慢字段 | 能。继续走现有缓存，不进 5 分钟总线 |

5 分钟一档的最新价**不是** 5 分钟 K 线：没有这一档自己的开高低收和成交量（除非麦蕊现价里本来就带、且我们原样记下），就不能画蜡烛。能画的是阶梯折线，以及用相邻档比较涨跌、是否离开买区/底部。

查询引擎、Agent、盯盘要现价时，只认胶带上带 `as_of` 的那一档，禁止再为「刷新一下」直连麦蕊（缺档且本机抢到写权限时除外，见第 4 节）。

### 2.2 墙钟切档（上海时区）

用墙上的钟，不用「距我上次打开过了五分钟」。

- 时区：`Asia/Shanghai`。
- 第一期间隔：`interval_sec = 300`。
- 档位：把当前时刻向下取整到间隔。例：10:00、10:05、10:10。**10:08 的当前档仍是 10:05。**
- 交易时段与现在调度对齐：工作日 09:00–15:00 检查档口（开盘前空档允许不写；一旦有人写了也保留）。收盘后不再为「最新价」开新档。20:20 复盘仍用日线，不读盘中最后一档冒充次日。
- 以后若改为约 1 分钟一档，只改间隔和文件名粒度，协议不变。不要在同一天混用两种间隔当两套真相；切换日从下一交易日起生效，旧档文件保留。

分析、表格、告警、对话上下文必须带 `as_of`（档位起始时刻），不要用「我本机读到文件的时刻」。

### 2.3 10:05 / 10:08 的正确行为

1. 10:05 A 的后台发现 `quotes/2026-09-20/1005.json` 不存在，打麦蕊，写入并 push。`as_of=10:05`，`writer=A`。
2. 10:08 B 先 pull，当前档仍是 10:05，文件已在 → **禁止打麦蕊**。界面、盯盘、分析师都用这一份，时间一律标 10:05。
3. B 的界面**不得**卡住等到 10:10。前台读 10:05；10:10 由后台再走同一套「先 pull 再决定写不写」。
4. 10:10 文件还不在、B 醒着 → B 写 10:10。A 若也醒着但 push 晚了，丢掉自己刚打的麦蕊结果，改用仓库里那一份。

### 2.4 抢写：挡的是双真相，不是物理上的双请求

档口起点四人同时醒，Git **不能保证**只有一次麦蕊 HTTP，只能保证**只有一份被接受的文件**。后 push 的人必须放弃本地结果。额度够用时，偶发两次可以接受。

若要再压双拉：档口开始后按本机身份散列等待 0～15 秒再尝试写档，通常只剩第一台碰到空文件。不要用 Git 里的 `*.claim` 当锁——多一串无意义提交，冲突面更大。

禁止 force push、禁止 rebase 已经推上去的档口、禁止改已存在的 `1005.json`。分析依赖「这个路径永远是那一刀」。

## 3. 两个仓库，互不掺和

### 3.1 产品仓库（现有）

- 继续忽略整个 `data/`、`.env`、`*.db`。
- 代码、文档、YAML 策略只在这里。
- 默认远程可继续是现在的 GitHub 源码库。

### 3.2 时钟仓库（新建，私有）

建议名：`stock-analyzer-clock`（最终以实际私有库为准）。四人都有推送权限。

各机克隆位置：**`data/clock/`**（位于已被产品仓库忽略的 `data/` 下）。产品的 `git status` 看不见行情文件。这是嵌套仓库，不是子模块——产品仓库不要用 gitlink 去指它，避免有人 clone 源码时被迫拉行情、或把时钟历史推进源码。

`.env` 增加例如：

```
CLOCK_REPO=          # 本机绝对路径，默认 <DATA_DIR>/clock
CLOCK_REMOTE=origin
CLOCK_INTERVAL_SEC=300
CLOCK_TZ=Asia/Shanghai
```

未配置或目录不是 git 仓库时：行为与今天相同（本机直连麦蕊 + 本机缓存），并在工作台标明「墙钟账本未启用」。不得假装多人已对齐。

### 3.3 远程放哪

第一期倾向：与源码同一 GitHub 账号下的**另一个私有库**，权限最省事。若 pull/push 经常因网络失败导致整档停摆，再加国内镜像做远程；协议不变，只换 `CLOCK_REMOTE`。不要把时钟仓库做成公开库。

Git 凭证必须能免交互（本机已登录的 Git Credential Manager 或 PAT）。后台不能在托盘里弹「请登录」。

## 4. 账本布局与文件契约

### 4.1 目录

```
stock-analyzer-clock/
  README.md                 # 给人看的间隔、时区、禁止改历史
  schema.md                 # 字段含义；版本与 JSON 内 schema 一致
  universe/
    <login>.json            # 每人一个，只许改自己的
  quotes/
    YYYY-MM-DD/
      HHMM.json             # 一档一个，写完永不改
```

- 最新档 = pull 之后 `quotes/` 下 `as_of` 最大的文件，或「当前墙钟档对应路径若存在则用它」。**不维护**可变的 `latest.json`。
- 日期文件夹按交易日（上海日历）。文件名 `HHMM` 为档位起始，24 小时制四位，如 `0930`、`1005`、`1300`。
- 不要按年/月再套一层，除非将来单日文件多到目录列表都慢（1 分钟一档再评估）。

### 4.2 档口 JSON

`quotes/2026-09-20/1005.json` 只描述这一刀横切面：

```json
{
  "schema": 1,
  "as_of": "2026-09-20T10:05:00+08:00",
  "interval_sec": 300,
  "writer": "hanish",
  "codes": ["000001", "600038"],
  "quotes": {
    "000001": {
      "p": 11.20,
      "pc": 0.52,
      "pe": 5.1,
      "sjl": 0.6
    }
  }
}
```

字段纪律：

| 字段 | 规定 |
|---|---|
| `schema` | 整数。不兼容变更才加一。读旧档必须能按版本解析 |
| `as_of` | 带 `+08:00` 的档位起始，不得写成写入瞬间 |
| `interval_sec` | 写入时的间隔，便于以后改 1 分钟后仍能读旧档 |
| `writer` | 本机登录名或稳定的节点名，只为事后知道谁补的档，不当权限 |
| `codes` | 这一档实际请求并集，排序稳定（字符串升序），减少 Git 无意义 diff |
| `quotes` | 键为 `code6`。值只含麦蕊现价里**已经返回**的标量。第一期最少 `p` / `pc` / `pe` / `sjl`（与现在 `quotes_many` 对齐） |

麦蕊现价若还带当日开高低或成交量：**原样多记，不编造。** 有则折线和「当日已实现高低」能厚一档；没有也不许用相邻档插值冒充这一档的 OHLC。缺的代码显式不写或写 `null` 字段，不要用别的股票的价填上。

单文件体积：小池子上百只、每只数个标量，约数 KB 到数十 KB。5 分钟、交易时段每天几十个文件，一年量级可接受。禁止把 `bars_*` 日线数组嵌进档口文件。

### 4.3 代码并集 `universe/<login>.json`

```json
{
  "schema": 1,
  "login": "hanish",
  "updated_at": "2026-09-20T09:12:00+08:00",
  "codes": ["000001", "600038"]
}
```

- 每人只 commit 自己那一个文件。自选增减、盯盘规则用到的代码变化时更新，**不要**每 5 分钟重写。
- 抢到写档的人：pull 之后读取 `universe/*.json` 全部 `codes` 做并集，再打 `ssjy_more`。
- B 不必在线：A 仍能拉到 B 上次登记过的票。这是「四人一起贡献」在代码表上的含义。
- 并集过大（误把全市场写进去）时：写档前设硬顶（建议默认不超过查询同步上限量级，与 `QUERY_SYNC_LIMIT` 同阶，可配置）。超限拒绝写档并打日志，避免一份 licence 被并集打穿。
- 个人成本、买区、持有逻辑**不**进 `universe` 文件。

### 4.4 Git 操作纪律（时钟仓库专用）

1. 只快进：`git pull --ff-only`。不能快进则停、报「账本分叉」，不要自动 merge。
2. 禁止 `--force`、禁止改已经 push 的档口文件、禁止 `commit --amend` 公共历史。
3. 档口文件只新增。`universe/<自己>.json` 可以覆盖写，因为没有第二个人改同一路径。
4. 一次写档一次 commit，说明写 `clock: 2026-09-20 10:05`。universe 变更另一次 commit，说明写 `universe: hanish`。不要把源码和时钟仓库交叉 cherry-pick。
5. 时钟仓库里不要放 LFS、不要放 zip、不要把 SQLite 拷进去。

人可以偶尔用普通 git 客户端看历史，但**查询时段不要走 `git log` / diff**。Git 只负责同步和备份；分析走文件路径（第 7 节）。

## 5. 运行时协议（每台机器相同）

后台定时器（盘中）或用户点「刷新现价」都走同一函数，避免两条路径。建议叫「对齐当前档」，不要叫「拉行情」。

```
pull --ff-only
计算 slot = floor(now_shanghai, interval)
path = quotes/YYYY-MM-DD/HHMM.json

若 path 已在本机工作区:
    使用该文件
    盯盘 / 表格 / 问答只读这份
    结束（零次麦蕊）

若 path 不在，且现在尚未进入该档（理论上不会，防御）:
    使用上一档（若有）
    结束

若 path 不在，且现在已进入该档:
    （可选）散列抖动 0～15 秒，再 pull 一次
    若此时 path 已在: 同上只读
    否则:
        并集 = union(universe/*.json)
        并集为空则并上本机自选（避免空档）
        若并集超硬顶: 失败，沿用上一档，记错误
        MarketClient.quotes_many(并集)     ← 本进程唯一允许的现价 HTTP
        原子写 path（先写临时文件再改名）
        git add + commit + push
        若 push 被拒:
            pull --ff-only（若仍不能快进则停并报警）
            删除或丢弃本地未接受的档口文件
            若 path 已由他人写入: 使用仓库那一份
            若仍没有: 本轮放弃，沿用上一档，等下一检查点
```

补充规则：

1. **启动探测**：账本已启用且最近一档未过期，跳过对 `000001` 等样本代码的 `ssjy` 探测，或只根据最近档判断是否 sample-only。避免四台开机各打三枪。
2. **GitHub 不可用**：本机继续用已经 pull 下来的最后一档，工作台标明「账本未刷新，现价停在 &lt;as_of&gt;」。**禁止**此时改去直连麦蕊当最新价展示，否则四人时间线分叉。
3. **本机无 licence 且当前档缺失**：不得凭空编价。只读上一档；若完全没有档，现价列为空并标明原因。有 licence 的同伴在下一检查点补档后，pull 即恢复。
4. **问到并集里没有的一只票**：不要为这一只破坏时间线、当场当最新价去打麦蕊。把代码写入自己的 `universe/<login>.json` 并 push，**下一档**并集才会带上。用户点名「现在立刻看这只」可以走显式的「单只补档外请求」，必须在 UI 标「非墙钟档、仅本机」，默认关、仅查询桌面手动触发，盯盘和 Agent 默认不用这条旁路。
5. **离线模式 `MAIRUI_OFFLINE=1`**：不写档口（避免把夹具样本推进私有库当实盘）。可以只读已经存在的档。演示 licence 同样禁止写档。
6. **非交易时段**：不新写现价档。读上一交易日最后一档时必须标明日期，不得显示成「现在」。

盯盘（`run_watcher`）改为：先对齐当前档，用档里的 `p`/`pc` 填查询引擎的 quote，再跑规则。命中记录里的 `hit_price` / 时间要能对应 `as_of`（可另存 `as_of` 字段；未改表前至少写进 `detail`）。复盘次日 K 线仍用 `market.history`，不把盘中档当成次日收盘。

调度建议：

- 档口对齐：每分钟醒一次，判断是否进入新档或当前档仍空（比「整点 5 分钟 cron」更能在 10:05:20 才开机的人补 10:05）。
- 规则扫描：可以仍 5 分钟一次，但**只读快照**，不再每人打一轮麦蕊。以后盯盘要 1 分钟一次，也只是更勤地读档 + 更勤地尝试补空档。
- universe 提交：自选 API 保存成功后异步 commit/push，失败记日志，不挡保存本机数据库。

## 6. 和本机 `data/`、MarketClient 的关系

`MarketClient` 仍是**唯一**允许对麦蕊发 HTTP 的模块（软件设计文档此条不变）。账本是它前面的一层决策：现价先问档口，没有档且本进程有权写才调用现有 `quotes_many`。

| 路径 | 是否共享 | 说明 |
|---|---|---|
| `data/clock/` | 是（git 远程） | 墙钟胶带 + universe |
| `data/cache/*.json` | 否 | 日线、名单等可再拉缓存，LRU 上限照旧 |
| `data/app.db` | 否 | 自选、规则、告警、会话 |
| `data/artifacts/` | 否 | 导出 Excel |
| `.env` | 否 | licence、模型 Key、时钟仓库路径 |

查询表刷新：慢字段（财务、股东、日线衍生底顶）继续本机缓存；现价列来自当前档。不要因为刷新表格就把并集再打一遍麦蕊。

工作台本机数据页（`GET /api/storage`）应能看到时钟仓库：是否已 clone、最后一档 `as_of`、最后一次 pull/push 成败。不在这里提供「删除某档」——删档等于改历史。

## 7. 时段分析、回放与绘图

### 7.1 查询 API（对内，读文件不读 git 对象）

| 能力 | 输入 | 输出 |
|---|---|---|
| `clock_slot(as_of)` | 档位或时间 | 那一刀完整 JSON；没有则明确空洞 |
| `clock_latest()` | — | 当前应使用的档（含是否过期、账本是否落后） |
| `clock_series(code, start, end)` | 代码 + 闭区间 | `[{as_of, p, pc, pe, sjl, ...}, ...]`，按时间升序，缺档跳过不插值 |
| `list_slots(date)` | 交易日 | 当天已有档的 `as_of` 列表 |

空洞就是当时没人在线，允许。禁止用前后档线性插值冒充「当时看到的价」。

### 7.2 和日线怎么一起用

| 问题 | 用什么 |
|---|---|
| 现在这只什么价、盯盘要不要响 | `clock_latest()` |
| 「今天 10:05 到 14:00 它怎么走」 | 当天 `clock_series` 连折线 |
| 「上周二 10:05 我们当时看见的全表」 | `clock_slot` 原样回放 |
| 「这周每天收盘离底多少」 | 麦蕊日线 + 现有底/顶算法 |
| 复盘「次日有没有同向」 | 日线第一根日期 &gt; `hit_date` 的收盘（智能体运行时已规定） |

不要把胶带上的点当成 5 分钟蜡烛。若以后麦蕊另有分钟 K 接口且官方有源，那是第二条数据集，另开缓存键，不覆盖墙钟档文件。

### 7.3 前端

- 查询表现价旁标明 `as_of`，过期未刷新时变文案，不假造跳动。
- 时段图：选代码 + 起止，画 `p` 的阶梯或折线，X 轴是档位。缺档断线或留空，不要连成假平滑。
- 「回放某一档」：用那一档的 quotes 填表，标题写死该 `as_of`，禁止同时再刷「最新」。

### 7.4 Agent

新增只读 Tool（有源才进 YAML 白名单），例如 `clock_slot`、`clock_series`。**禁止**把一天 48 个文件塞进提示词。模型拿到序列摘要或已经算好的「从 10:05 到 14:00 涨了多少 / 是否离开买区」。图画在前端。分析师引用必须带 `as_of` 或时间区间，与现在「只引用 Tool 数字」一致。

researcher 看市场仍用今日队列、盯盘命中；需要「今早以来自选怎么走」时调 `clock_series`，不要再扫一遍麦蕊。

## 8. 后台挂机

账本要在「没人盯着黑窗口」时仍往前走，助手必须变成**关界面也不退出**的本机进程。现在 `scripts/run-server.cmd` 关窗口等于杀 uvicorn，10:10 就没人写档。

挂机形态（由轻到重，第一期不必上 Electron）：

1. 启动后可最小化；增加「退出 / 仅隐藏」区分。
2. 托盘图标：打开工作台、显示最后一档 `as_of`、手动对齐当前档。
3. 开机启动（用户自愿）。
4. 智能体运行时里的 **S9 Electron + 托盘** 仍可在更后做；本文不把账本绑定到 Electron。

后台循环就是第 5 节协议 + 本机 `run_watcher`。四台都挂着覆盖最好；只剩一台时它就是当天的记录仪；四台全关，胶带在上一档断开——没有常开主机时这就是上限。

告警、复盘结论、webhook 仍只写本机。Git 里没有「谁的告警」，避免把个人持仓逻辑推到共享历史里。

## 9. 安全

- 时钟仓库私有。协作者仅此四人。
- licence、模型 Key、`APP_SECRET`、登录口令不出现在档口 JSON、commit message、universe 文件里。
- 产品进程仍绑 `127.0.0.1`。不要为了共享快照把整站放到局域网；若将来同一 Wi‑Fi 要做「局域网读最新档、Git 异步归档」（1 分钟一档才需要），也只暴露只读快照端口，带共享口令，不暴露查询/Agent/数据库。
- 演示 licence / 离线夹具不得 push 进时钟仓库。
- 不在时钟仓库开 GitHub Actions 去打麦蕊（那会变成云上取数员，与「不部署服务端」和钥匙不出门相悖）。

## 10. 故障与降级

| 情况 | 行为 |
|---|---|
| 当前档已在 | 只读，零麦蕊 |
| 当前档不在，本机有 licence，push 成功 | 本机写档，成为这一档的 writer |
| push 被拒，pull 后档已在 | 丢弃本机麦蕊结果，用仓库 |
| 不能快进（有人非快进合并了） | 停止自动写档，界面报账本分叉，人工按「只保留 origin、不改已有档口」处理 |
| 远程失败 | 只读本地最后一档，标明落后，不直连麦蕊冒充最新 |
| 无 licence | 只读；不写档 |
| 并集超硬顶 | 不写档，记错误 |
| 麦蕊失败 / sample-only | 不把样本写入账本 |
| 时钟不准 | 仍以文件名和 JSON 内 `as_of` 为准；切档用上海墙钟。差几十秒仍应对齐同一档，不要用本机「我觉得过了五分钟」 |
| 某档全天缺失 | 分析时跳过该 `as_of`，允许空洞 |

## 11. 间隔从 5 分钟到约 1 分钟

第一期必须先用 5 分钟跑通：冲突率、国内访问 Git 远程的抖动、后台免登录 push。

1 分钟一档时：文件数大约乘 5，GitHub 一天几百次 push 通常仍可；但 pull+push 一轮若要数秒到十几秒，会咬掉档口。那时再拆成：

- **最新档**：局域网或本机内存，低延迟读；
- **归档**：仍然不可变文件，异步 push 进同一时钟仓库。

协议（一档一文件、只增不改、先 pull 再写）不变。未到这一步不要上局域网端口。

体积：5 分钟、小池子、只存现价标量，私有库挂几年通常不是问题。不要为此上 Git LFS。

## 12. 分期落地（本文范围内）

S0–S9 仍只认软件设计文档第 12 节。下面是账本自己的顺序，**未实现前不要改 MarketClient 行为装成已对齐**。

| 步 | 交付 | 完成标准 |
|---|---|---|
| **C0** | 私有时钟仓库 + 本文约定的目录/JSON + 四人权限 | 空库可 clone 到 `data/clock/`；产品仓库仍看不到这些文件 |
| **C1** | 只读：pull + `clock_slot` / `clock_series` / 工作台标明 `as_of` | 人工放一档 JSON 也能回放、能画折线；还不打麦蕊写档 |
| **C2** | `MarketClient` 现价：先问当前档，缺档才 `quotes_many`，成功则 commit/push；冲突则弃本地 | 两台机器同一档不会留下两个文件；演示 licence 写不进去 |
| **C3** | `universe/<login>.json` 随自选保存更新；写档打并集 + 硬顶 | A 开机能拉到 B 已登记而未开机的票 |
| **C4** | 盯盘与查询表吃当前档；启动探测不再无条件打 `ssjy` | 四人开着盯盘，空档以外麦蕊现价请求约等于档口数，而不是人数 × 档口数 |
| **C5** | 时段折线 + Agent 只读 Tool | 引用带时间；不把全天 JSON 塞进模型 |
| **C6** | 关界面不杀进程（托盘或等价物）+ 免交互 git | 没人开浏览器时仍能补档 |

建议 C1 即可开始用历史副本讨论绘图；C2 才真正「只查一次」。不要先做托盘再做账本，否则后台只是四台继续重复打麦蕊。

## 13. 和现有模块怎么接（防漂）

| 概念 | 将来代码大致落点 | 现在 |
|---|---|---|
| 切档、路径、JSON schema | 建议 `src/market/clock.py` | 无 |
| pull / commit / push | 同模块，只操作 `data/clock/` | 无 |
| 现价是否打麦蕊 | `MarketClient.quote` / `quotes_many` 开头 | 每次 HTTP |
| 代码并集 | 自选写入后更新 `universe/<login>.json` | 自选只在 SQLite |
| 盯盘读档 | `run_watcher` 前对齐当前档 | 经 QueryEngine 直连 quote |
| 调度 | `scheduler.py` 增加「每分钟尝试对齐」；规则扫描可仍 5 分钟 | 仅 `*/5` session + 20:20 eod |
| 查询表 `as_of` | 前端 + 查询 API 返回档位 | 无 |
| Agent Tool | `src/tools/` + analyst/researcher YAML 白名单 | 无 clock_* |
| 本机占用页 | `/api/storage` 增加时钟仓库状态 | 仅 cache / db / artifacts |

禁止：Tool 自己 `git push`；Agent 自己拼麦蕊 URL；watcher 为规则再开一条现价 HTTP。

## 14. 明确不做（账本范围）

- 不把产品做成公网服务，不为账本引入云函数去代打麦蕊。
- 不把时钟仓库当通用数据库（财务、股东、日线、对话、告警都不进）。
- 不把 Git 当分布式锁服务（不用 claim 文件、不用锁分支）。
- 不把档口插值成假 K 线，不把空洞补成「应该有过的价」。
- 不在问答里用墙钟数据荐股或自动改规则。
- 不把四人的 `app.db` 做同步或合并。
- 第一期不上局域网快照端口（见第 11 节）。

## 15. 已定倾向与仍可调的点

已定：

- 四人都是取数员；一档一文件；只增不改；先 5 分钟；独立私有 Git；克隆在 `data/clock/`；现价与日线分工；后台挂机是监控的前提而不是网关机。
- 字段按麦蕊现价**原样多记不编造**；最少包含现在的 `p/pc/pe/sjl`。
- 时钟仓库第一期与源码同在 GitHub 私有库，网络不行再加镜像，不改协议。

实现前仍可微调、但不改变模型的：

- `CLOCK_INTERVAL_SEC` 的具体数字（300 或 60）。
- 并集硬顶的具体上限。
- `writer` 用登录名还是主机名。
- 抖动等待的秒数（0～15 只是量级）。
- 单只「非墙钟」旁路要不要在查询桌留手动开关（默认建议关）。

改「一档一文件 / 两个仓库 / 现价不得无账本直连展示」任一则先改本文，再改代码。
