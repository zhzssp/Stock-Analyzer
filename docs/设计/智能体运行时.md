## 0. 一句话

本机自选助手：小池子里把数问清、把变化盯住、把隔夜结果标上。不下单、不荐股、无源不开槽。

运行时学工业界常见的 **Mode A 分层，按本机裁剪**：外壳自研管控；内层编排默认同构的 `plan → tool → observe → 作答` 循环；LangGraph Pregel 只作为将来某类「挂起-分叉」角色的可选实现，不迁现网。

## 1. 四个角色（两个聊天，两个作业）

| id | 形态 | 职责 | 触发 | 前端 |
|---|---|---|---|---|
| `analyst` | 交互 | 点问取数，只引用 Tool 数字；遵守用户监控守则 | `POST /api/agent/chat`，默认或点名 | Agent 问答 |
| `researcher` | 交互 | 看市场；注入今日队列、盯盘命中、次日复盘摘要 | 「看市场」或路由词 | 同一问答页，不另开顶栏 |
| `watcher` | 调度作业 | 今天该不该打断你：模板规则 + 自定义规则 + 决策卡 | 盘中 5 分钟、20:20、手动跑 | 监控中心「今日 / 规则 / 偏好」 |
| `reviewer` | 调度作业 | 昨天那条隔夜像信号还是噪音 | 20:20 在 watcher 之后；`POST /api/monitor/review/run` | 监控中心「复盘」，**不是**第四个顶栏智能体 |

禁止合成超级 Agent。禁止问答里 `agent=reviewer`。禁止按复盘分数自动关闭规则或下单。

策略与打分阈值在 YAML，不写进某个巨型 prompt：

- `config/agents/analyst.yaml` / `researcher.yaml`：工具白名单、`max_rounds`、守则、plan/write prompt
- `config/agents/reviewer.yaml`：同向 / 反向阈值、哪些 job 按涨跌打分、哪些只观察

Python 改完必须重启服务（Uvicorn `reload=False`）。改上述 YAML 可用 `POST /api/agent/tools/reload` 重载策略，不必热更新进程。用户在监控中心写的规则定义 / 监控需求是运行时上下文，不写进 YAML；改完保存即对下一轮问答生效。

## 2. Mode A：三层，外壳永不换成图库

```
┌─────────────────────────────────────────────┐
│ 管控运行时（外壳，继续长）                      │
│ FastAPI 鉴权 · agent_sessions · policy YAML    │
│ Tool 注册表 / 白名单 · llm.py 模型路由          │
│ APScheduler · bus / channels · SSE 事件流      │
└─────────────────────┬───────────────────────┘
                      │ 只认 tool / token / done
                      ▼
┌─────────────────────────────────────────────┐
│ 编排槽（内层，可替换）                          │
│ 默认：src/agents/runner.py 直线超步             │
│ 可选（未接线）：LangGraph Pregel + 自研         │
│   CheckpointSaver（与业务表分表）               │
└─────────────────────┬───────────────────────┘
                      │ 只打网关，禁止直连麦蕊
                      ▼
┌─────────────────────────────────────────────┐
│ 能力平面                                       │
│ registry.run · QueryEngine · MarketClient     │
│ watcher 规则 · reviewer 状态机                 │
└─────────────────────────────────────────────┘
```

| 层 | 现在 | 只允许的长法 |
|---|---|---|
| 外壳 | 已具备缩小版 | 权限、run 日志、有限重试、`always_tools` / `forbidden` 硬执行。不换成 LangGraph Server / LangSmith |
| 编排槽 | `iter_agent` 唯一实现 | 抽出同一事件协议。默认循环；仅新角色需要挂起/人在环中且批处理写不清时，才把 Pregel 作为第二种实现 |
| 状态 | SQLite 业务表 | 会话 / 告警 / 自选仍业务表。若上图，checkpoint **另表**，禁止替换 `agent_sessions` |
| 工具与模型 | `registry` + `llm.py` | 节点只调这两处。不引入 LangChain Tool / ChatOpenAI 当生产路径 |
| Watcher / Reviewer | 规则 + 状态机 + cron | 留在外壳调度。不进对话图，也不进 Pregel |

`src/agents/graph.py` 只是 `run_analyst` 的薄包装。依赖里可以留着 `langgraph`，代码默认零引用。

### 2.1 问答循环（已落地，不是经典 ReAct 文本协议）

最多 `max_rounds`（默认 3）：`plan()` → 执行白名单 Tool → `observations`；没有新调用则停，再 `write_answer`。有 Key 且模型支持 tool calling 时走 DeepSeek 兼容接口；否则关键词启发式。无 Key 必须仍能取数、用模板拼答案。

HTTP 与测试只认三种事件：`tool` / `token` / `done`。换内层实现不得改这三种名字。

### 2.2 跨日分支（已落地，不是 Pregel）

「跨日分支」= 一条提醒在库里的状态机，不是把 analyst 改成图。

```
pending ──无下一根交易日K线──► pending 或 deferred
      ├──方向规则且次日符合预期──► helpful（次日同向）
      ├──方向规则且次日相反────► noise（次日反向）
      ├──有K线但波动小于阈值──► mixed
      └──股东/资金/事件────────► skipped（不按涨跌打分）
```

命中时必须写下 `hit_price` / `hit_date`。到期条件：`hit_date < 今日`，取 `market.history` 里 **第一根日期 > hit_date 的收盘**。不用当天 20:20 的价冒充次日。关机再开 `pending` 仍在。

这与 watcher 的「每天再扫一遍 + Snapshot diff」不是同一件事：后者是跨日批处理，前者是同一条命中的挂起-唤醒。

### 2.3 何时才引入 LangGraph

四条同时满足才动手，并且是 **加适配器，不是迁现网**：

1. 已承诺做一个现循环写不清楚的新角色。
2. 该角色需要条件边、等待、人在环中或跨进程恢复。
3. 不能改写成确定性规则或一条 SQL / 状态机批处理。
4. 适配现有 `registry.run` 预计不超过一天。

到点时：新建例如 `src/agents/graphs/<role>.py`，节点调用现有 `plan` / `_run_one` / `write_answer`；按 `agent` 名分流。analyst / watcher / reviewer 默认不动。

## 3. 前端入口纪律

工作台顶栏只保留三块：**传统查询 / Agent 问答 / 监控中心**。

- reviewer 的展示入口是监控中心「复盘」子页 + 「今日」提醒行上的标签。
- researcher 在回答里复述复盘摘要，不另开顶栏。
- 不要第四个「复盘智能体」聊天页，不要问答里可选 `reviewer`。

以后加深（不是缺入口）：复盘页画出 API 已有的按规则计数 `by_job`；查询表可选「上次命中的次日标签」列。

## 5. 明确不做

- 不为对齐旧文档把 analyst / watcher / reviewer 重写成 StateGraph。
- 不上超级 Agent；路由显式（YAML + `pick_agent` + cron），不让模型猜该谁干活。
- 无源不启用 Tool，工作台不画假行情。
- 不荐股、不下单、不按 AI 评分排序自选。
- 无 LLM Key 时启发式规划必须继续能答。
- 用 checkpoint 当自选库、告警库、对话库。
