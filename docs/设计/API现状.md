## 0. 一句话结论

现有表格里的**原始数据列**（行情、市值、财务、分红、补贴收入、X日价）API 全部能取到；但表格的**核心逻辑列**——「底 / 顶 / 离底% / 高底% / 倍数 / 目标卖价」这一整套——API **不直接提供，必须自己算**，算它们所需的日线接口是给的。

股东股本、前十大流通股东**都有**（两套接口）。公告、问董秘、订单流、按日逐笔/资金流向、交易日历、券商板块树、Quant Pro 1 分钟、分析页上的龙虎榜/南北向等，**官网 2026-09 已列出**；本仓库查询表大多尚未接。

初版两个「未识别列」已查清（见 §3），**图 1 原始字段不缺源**。南北向全市场路径在 [hanalyse](https://www.mairuiapi.com/hanalyse)，**盖不住「自选每只每日北向」**，见缺口文。

⚠️ **硬前提未变：** 标准 `hsstock/history` 不设 `st`/`et` 时只写「全部历史数据」，**未定义回溯到上市日**（见 §4.5）。「17年后底」必须正式 licence 实测。

## 2. 查不到 / 必须自己算的信息

现有表格的核心列全部落在这一区。API 没有任何「N年最高/最低价」类字段，也没有任何估值目标价字段。

| 表格中的列 | API 状态 | 计算方式 | 所需原料 |
|---|---|---|---|
| **底 / low**（近1年底、17年后底） | ❌ 无 | 区间 `min(l)` | `hsstock/history` 日线 |
| **顶** | ❌ 无 | 区间 `max(h)` | 同上 |
| **离底%** | ❌ 无 | `(现价 - 底) / 底` | 现价 + 上面算出的底 |
| **离1年底%** | ❌ 无 | 同上，区间取近1年 | 同上 |
| **高底%** | ❌ 无 | `(顶 - 底) / 底` 或 `现价/顶` 类比值 | 顶 + 底 |
| **底一贯 / 层一贯（倍）** | ❌ 无 | 顶底倍数 `顶 / 底` | 顶 + 底 |
| **目标卖价**（表头注明「底涨50%」） | ❌ 无 | `底 × 1.5` | 底 |
| **比价差%** | ❌ 无 | `(目标卖价 - 现价) / 现价` | 现价 + 目标卖价 |
| **比日涨跌%** | ❌ 无 | 自定义对比口径 | 实时 `pc` |

**可行性结论：全部可算，但有一个前提待实测。** `hsstock/history` 不传 `st`/`et` 时返回「全部历史数据」——原文用词就是这四个字，**并未定义历史深度**。「日线以上为上市以后所有数据」这句话在原文中**只出现在企业版接口的说明里**，不能想当然套用到标准接口上。

> ⚠️ **「17年后底」这一列的可行性，完全取决于标准 `hsstock/history` 的实际回溯深度。这是整套方案唯一的硬前提，必须第一步就实测验证**（详见 §4.5）。

**⚠️ 口径必须先定：** 该接口支持 5 种复权方式。从截图数据推断（中直股份 底 24.6 / 现价 26.86），现有表格用的是**不复权 `n`**。若改用复权价，所有底/顶/倍数结果都会变，需保持全表一致。

**部分可省力：** 3日/5日/10日涨幅与换手可直接取 `hsstock/indicators`；60日涨跌幅、年初至今涨跌幅可直接取 `hsrl/ssjy` 的 `zdf60` / `zdfnc`，不必自算。

## 3. 曾未识别的列（已全部解决 ✅）

初版文档中有两列表头因图片压缩而误读。放大原图后两列均已确认，且**两列 API 都能直接支持**。

| 位置 | 初版误读 | 实际表头 | API 状态 |
|---|---|---|---|
| 图1 倒数第3列 | ~~补股收入~~ | **补贴收入** | ✅ 利润表 `btsr` |
| 图2 最左列 | ~~3 日价~~ | **X 日价**（X 为可输入日期） | ✅ 日线 `history` 指定日期 |

### 3.1 补贴收入 → `btsr`

表头因列宽过窄被折行显示成「补贴收 / 入」两行，初版误读为「补股收入」。

`hsstock/financial/income`（利润表）中有现成字段：

```
btsr    float    补贴收入
qtsy    float    其他收益
```

**为什么整列都是 `–`：** 这不是 API 缺数据，而是会计准则变更所致。2017 年财政部修订《企业会计准则第 16 号——政府补助》后，与日常经营活动相关的政府补助不再计入「补贴收入」，改列报于「**其他收益**」。因此近年报表中 `btsr` 基本恒为空，真实数据落在 `qtsy` 上。

**✅ 已实测证实**（`hsstock/financial/income/000001.SZ`，2025 年三期）：

| 截止日期 | `btsr` 补贴收入 | `qtsy` 其他收益 |
|---|---|---|
| 2025-09-30 | 空 | 56,000,000 |
| 2025-06-30 | 空 | 50,000,000 |
| 2025-03-31 | 空 | 43,000,000 |

> ⚠️ 该接口对空值返回的**不是 JSON `null`，而是字符串 `"-"`**，判空逻辑必须同时处理 `null` / `""` / `"-"`（脚本中的 `Test-Blank` 即为此）。

> **建议：** 取数时用 `qtsy`（其他收益），或 `btsr` 为空时回退到 `qtsy`。若坚持照搬原表口径，则该列在现行准则下本就应为空。

### 3.2 X 日价 → 指定日期收盘价

这一列不是固定指标，而是一个**带日期参数的查询列**：表头下方 `20260305` 是输入框，填什么日期，整列就显示各股在该日的收盘价。

反推验证（20260305 = 2026年3月5日）：

| 代码 | 名称 | X日价 | 底 | 现价 | 顶 |
|---|---|---|---|---|---|
| 600038 | 中直股份 | 37.05 | 24.6 | 26.86 | 80.45 |
| 000725 | 京东方A | 4.46 | 2 | 5.78 | 9.1 |
| 002230 | 科大讯飞 | 52.19 | 16.55 | 41.25 | 80.4 |
| 000988 | 华工科技 | 106.61 | 9.43 | 107.85 | 184.61 |

全部 40 行的 X日价均落在各自 `[底, 顶]` 区间内、且与现价同量级，可确认为历史某日价格而非目标价或均价。

**取数方式：**

```
GET hsstock/history/{code}.{市场}/d/{复权}/{licence}?st=20260305&et=20260305
→ 取返回记录的 c（收盘价）
```

> **两个注意点：**
> 1. 若指定日为非交易日或该股停牌（`sf=1`），该日无数据，需回退到最近一个有效交易日。
> 2. 复权口径要与「底/顶」保持一致（见 §2），否则同一行内的价格不可比。

**顺带一提：** 这一列既然已经从日线缓存里取，就无需额外调接口——§5 第 2 步的本地日线缓存可以直接支撑任意「X 日价」查询，且切换日期时零 API 消耗。

### 4.6 🆕 新增 — 代码参数格式在同一接口族内不统一

这是最容易踩的实现坑。**不能简单记成「`hsstock` 用后缀、其他不用」**，因为 `hsstock` 族内部就不一致：

| 需带 `.市场` 后缀（如 `000001.SZ`） | 只要 6 位纯代码（如 `000001`） |
|---|---|
| `hsstock/latest`、`hsstock/history` | `hsstock/real/time`、`hsstock/real/five` |
| `hsstock/stopprice/history`、`hsstock/indicators` | `hsstock/history/transaction` ⚠️ |
| `hsstock/instrument`、`hsstock/financial/*` | `hscp/*` 全部、`hsrl/*` 全部 |
| `hsstock/history/{macd,ma,boll,kdj}` | `bj/*`、`kc/*`、`fd/*` 全部 |

⚠️ 特别注意 `hsstock/history/transaction`（资金流向）——它在 `hsstock/history/` 路径下，却是**纯代码**，与同前缀的 `hsstock/history/macd` 等相反。

**⚠️ 实测后结论反转——文档对 `hslt/list` 返回值的描述是错的：**

| 字段 | 文档描述 | **实测真实值** |
|---|---|---|
| `dm` | `000001`（纯 6 位） | **`000001.SZ`（已带后缀）** |
| `jys` | `"sh"` / `"sz"`（小写） | **`"SZ"`（大写）** |

也就是说：调用 `hsstock/*` 时**无需拼接后缀，直接用 `dm` 即可**；反而调用 `hscp/*`、`hsrl/*`、`bj/*`、`kc/*`、`fd/*` 时需要**主动把后缀去掉**。这与初版给出的建议正好相反。

> **应对：** 在数据层统一封装 `code6()`（截断到 6 位）和 `codeFull()`（直接用 `dm`），按接口查表决定用哪个，不要在调用处手写。
>
> ⛔ 各接口究竟接受哪种写法，需用正式 licence 跑 `Verify-Api.ps1` 的 T2 项确认（演示 licence 忽略代码参数，测不出来）。

## 5. 落地建议（顺序）

> **第 0 步是前置校验，不通过则后续方案需重新设计。**

0. **【必做】取得正式 licence 后运行验证脚本**：

   ```powershell
   .\scripts\Verify-Api.ps1 -Licence "你的licence"
   ```

   重点看报告中的 **T3+T4（历史回溯深度）**——这一步决定「17年后底」整套逻辑是否成立（见 §4.5、§4.7）。同时会一并验证 T2 代码参数格式、T9 跨市场支持。
   
   ⚠️ 用演示 licence 跑没有意义：它忽略股票代码、只返回固定样本，脚本会自动识别并标记 ⛔。
1. 用 `hslt/list` 建立股票池，落库；`dm` 本身已带后缀（如 `000001.SZ`），调 `hscp/*`、`hsrl/*` 时需截断为 6 位（见 §4.6）。
2. 用 `hsstock/history`（日线、不复权、全历史）**一次性全量抓取并本地缓存**，此后每日增量追加。当前池仅 40 只，无限频压力。
3. 在本地基于日线缓存计算：底、顶、离底%、离1年底%、高底%、倍数、目标卖价、比价差%。
4. 用 `hsrl/real/all`（或分批 `ssjy_more`）刷新实时列：现价、涨跌%、换手%、市值、PE、市净率。
5. 用 `hsstock/financial/pershareindex` + `income` 补财务列：净资/股、每股未分配利润、营业总收入、研发费用、补贴收入（`btsr`，为空则回退 `qtsy`）。
6. 用 `hscp/jnfh` 补分红列（每10股派$，返回历年数组）。
7. 用 `hsstock/financial/topholder` / `flowholder` / `capital` / `hm` 补股东股本模块。
8. 「X 日价」直接查第 2 步的本地日线缓存，无需额外调接口；注意非交易日/停牌回退。
