# 数据能提供什么（白话）

> 对照日期：**2026-09-22**（§6.1–§6.5、§7.5–§7.6 为次数、列依赖与现网问题归纳）。麦蕊官网现网页为准；仓库里的 `新API文档.docx` 是旧清单，不要再当目录。
> 分工见 [`../INDEX.md`](../INDEX.md)。「软件里有没有这一列」以代码和对客说明为准；本文说的是**数据商已经卖什么**，以及**还没接到工作台上、但可以拿来补哪一块**。
> 前半给看盘的人；后半给改软件的人（网址、路径、坑）。

---

## 1. 先用一句话说清楚

麦蕊像一家「卖股市数字的店」。我们这套软件是本机助手：自选、一张分析表、白话问答、监控提醒。店里有的，软件才可能显示；店里没有的，软件不能编。

**表上的现价、涨跌、市值、财务、股东、分红，店里都有。**  
**「底、顶、离底%、目标卖价」店里不直接卖，要用每天的高低价自己算。** 算它们需要的「每天一根棒」是有的；能不能算到十几年前，要实测日线到底有多长，不能想当然。

**2026 年 9 月对照官网后：店里比两个月前那份旧清单多了很多货。** 其中「某个指数里有哪些股票」我们已经接到「行情」入口；其它多数还在店里、没摆上工作台。

## 2. 软件现在已经在用的（打开就能对上的）

这些不是新货，是你现在查询表、问答、监控已经在吃的：

| 你在软件里看到的 | 人话 |
|---|---|
| 最新价、涨跌幅、市盈率、市净率、换手、市值 | 这只股票此刻贵不贵、成交活不活 |
| 60 日涨幅、今年以来涨幅 | 近两个月、今年到今天走了多少 |
| 行业、主营、七大板块 | 它是干什么的 |
| 前十大股东、流通股东、总股本 / 流通股本 | 谁拿得多、盘子多大 |
| 每股净资产、每股收益、研发费用、毛利率 / 净利率 | 报表上薄薄一层 |
| 资金流入、流出、净流入 | 当天大单进出的一个汇总，**不是北向** |
| 近 1 年底、更长的底和顶、离底%、目标卖价 | **软件用日线自己算的**，不是店里现成一列 |
| 分红 / 增发 / 解禁 | 监控「公司事件」在盯有没有变化 |
| 沪市全部、深市全部、北交所全部 | 各交易所挂牌名单 |
| **上证指数、深证成指、北证50、上证50、中证500、创业板指的成份股** | **这次已接通**：按指数名单查/导，不是把整个交易所冒充成指数 |

科创综指店里的「指数树」没有这一支，软件不会拿科创50或科创板全部来凑。北交所财务、股东常常空，以前文档也说过京市能力弱；官网后来补了京市报表和日线，**软件查询表还没改接**，所以格子仍可能空。

## 3. 这次对照官网后，新确认「店里有、可以去取」的

相对 2026-09-02 那份约 74 条旧清单，以及当时「指数成份不知道有没有正式接口」的判断，下面这些是**新确认有货**的。有的我们已经接了，多数还没摆上表。

### 3.1 已经接到软件里的新增

| 新确认的内容 | 人话 | 软件里现在怎样 |
|---|---|---|
| 指数成份名单 | 「上证指数里到底有哪些股票」有官方名单，不是猜路径 | 「行情」选指数，查/导只含成份股。现网已跑通上证约两千只、深成指 500、北证50 等 |

### 3.2 店里有、查询表还没当成正式列的（hsdata 沪深基础）

| 新能查到的 | 人话 | 现在软件 |
|---|---|---|
| 问董秘 | 投资者问公司、公司书面答复 | 没有入口 |
| 交易所公告列表 | 这家公司发过哪些公告标题 | 监控事件主要靠分红/增发/解禁摘要 + 巨潮链接，**没有公告分类** |
| 涨跌停当天表现 | 这只票今天怎么封的、封了多久一类盘后数字 | 没有涨停/跌停提醒任务 |
| 集合竞价表现 | 开盘前那几分钟怎么定价 | 没有 |
| 订单流（按日、盘后） | 更细的买卖力量切片 | 资金列只有汇总流入流出 |
| 指定某一天的逐笔成交 | 那天每一笔（有起始日期限制） | 没有给用户点选 |
| 指定某一天的资金流向 | 那天大单进出，不必只看「最新这一档」 | 资金列偏当天 |
| 交易日历 | 哪天开市、哪天休市 | 指定某日收盘价还没做；休市回退也没做成功能 |
| 券商的板块树、板块里有哪些股 | 比「名字里带两个字就算这个概念」更接近官方篮子 | 概念筛选仍是关键词，不是官方成分 |
| 1 分钟很细的走势 | 要更高档套餐（Quant Pro / 企业版） | 位置计算用日线，不用 1 分钟 |

### 3.3 分析中心另开的货架（hanalyse）

这些在「沪深分析 / 数据中心」那一摊，**不是**基础行情页同一套：

| 新能查到的 | 人话 | 注意 |
|---|---|---|
| 龙虎榜、今日交易提示 | 谁在席位上买得凶 | 软件监控没有龙虎榜任务 |
| 融资融券、大宗交易 | 借钱做、私下大宗 | 未接 |
| 机构持股（分析口径） | 和自选表上的「十大股东」不是同一张表 | 监控有「活跃资金持股」，吃的是基金持股那路 |
| 板块资金、个股资金排名、资金路线图 | 今天钱往哪个行业涌 | 未做成列或芯片 |
| 南北向资金（沪股通、深股通这类） | **全市场或大盘一条线**，不是「你自选每一只、每一个交易日」 | 表上「北向」列现在是空的，**这一摊仍然补不满那一列** |
| 可转债 | 另一类品种 | 软件不做转债池 |

### 3.4 其它市场文档变厚了

| 市场 | 以前旧清单给人的印象 | 现在官网写了什么 | 软件 |
|---|---|---|---|
| 北交所 | 几乎只有名单和现价 | 日线、报表、股东也可以查（要实测真假） | 表上北交所财务/股东常空 |
| 科创板 | 好像要单独再拉一份名单 | 沪深股票名单里已经含 688 | 沪市全部已含科创；K 线跟沪深同一套更稳 |
| 基金 / ETF | 另有文档 | 净值和档案在 | 本软件不做基金池 |
| 指数点位 | 一直有 | 仍是点位和 K 线，**不含成份股** | 顶栏上证/深成/科创点位；成份走上面 3.1 |

### 3.5 店里仍然没有、不要指望这次更新

| 你可能想要的 | 为什么没有 |
|---|---|
| 随便搜全网新闻、彭博快讯 | 麦蕊不卖新闻检索 |
| 原油、铜、股指期货的实时价格 | 没有品种行情，只有「这只股票名字上像哪个品种」 |
| 出口占收入多少 | 没有；软件只认你自己放的一张表 |
| 并购、回购的起止日结构化字段 | 公告列表没有这种分类标签 |

## 4. 这些新货，可以拿来完善软件的哪一块？

按「对你已经在用的功能最有帮助」排序。括号里是欠账编号，方便以后对表，不是开工令。

### 4.1 马上对得上、收益最大

**1）概念 / 板块筛选（欠账 U7）**  
现在点「2026 概念」是拿关键词去碰文字，会漏、会误伤。店里有「概念代码 → 成分股名单」，和指数成份是同一类取法。接上之后，筛选可以变成「官方篮子里的股票」，和「行情按指数导出」同一套规矩。

**2）涨停 / 跌停提醒（欠账 U15）**  
店里有涨停池、跌停池，还有单只股票当天涨跌停表现。可以做成：自选或关注池里有人涨停/跌停 → 进监控「今日」。这比现在只有资金异常、离底、减仓更靠近盘中情绪。

**3）指定某日收盘价（欠账 U14）**  
旧表有一列「填一个日期，看那天收在哪」。原料就是日线，交易日历能告诉你那天开不开市。软件已经在用日线算底和顶，**多一个日期框就能复用同一份缓存**，不必再买新种类的数据。

**4）3 日 / 5 日 / 10 日涨幅（欠账 U13）**  
表上已有 60 日、今年以来。店里有现成的短周期涨幅和换手，不必自己从日线加总。适合加进「列设置」里默认不勾、需要再打开。

**5）北交所空格子**  
若京市日线和报表实测能通，北交所那几只就不必整列空着。这是补现有表，不是新功能。

### 4.2 能加强「监控」和「问答」，但要克制范围

**6）公告 + 问董秘**  
监控现在只能发现「分红/增发/解禁摘要变了」。接上公告列表，问答可以引用「最近发了什么标题 + 链接」，不必假装有全网新闻（新闻仍然没有）。并购回购若只要「有没有公告」可以部分缓解；若要起止日结构化，公告接口仍然不够（欠账 U8）。

**7）订单流、按日逐笔、按日资金**  
可以把「资金异常」从「相对近几天均值」做成「指定某日、分大单小单」。问答可以回答「昨天主买多还是主卖多」。会多耗次数，适合只打自选，不要打全市场。

**8）集合竞价、涨跌停表现**  
适合盘后复盘和「今日」里多一条「开盘定价异常 / 封板质量」，不要做成荐股。

**9）龙虎榜、机构席位、板块资金**  
适合 researcher「看市场」多一段「今天钱去了哪、席位上有谁」，以及监控里一条可选的「自选上榜」。不要做成全市场选股器。

**10）交易日历**  
指定日收盘、监控「只在交易日跑」、墙钟档口跳过周末，都用得上。

### 4.3 接了也解决不了、或性价比低

**11）南北向全市场序列**  
补不满「自选每一只、每一个交易日的北向」。要么对客继续写「这一列空着」，要么改口径成「只看大盘北向」，不要把全市场曲线贴到每只股票上充数（欠账 U5）。

**12）1 分钟 K 线**  
要更高档套餐，对「离底、目标卖价」这种日线逻辑帮助不大。除非以后做盘中秒级盯盘，否则先不做。

**13）可转债、基金档案**  
和当前「A 股自选助手」不是同一条产品线，默认不接。

**14）期货价格、出口占比、全网资讯**  
这次官网更新**没有**补上。监控灰卡、问答「问了也是没有」应保持，不要用相关股票名单假装有期货价。

## 5. 必须自己算、或永远算不准的

| 表上的想法 | 店里 | 怎么办 |
|---|---|---|
| 近 1 年底、十几年底、顶 | 没有现成一列 | 用每天最高最低自己找；「十几年」取决于日线有多长 |
| 离底%、顶底倍数、底再涨一半当卖价 | 没有 | 现价加上面算出来的底 |
| 某日收盘（X 日价） | 没有单独一列，但日线里有那天 | 填日期去日线里取；休市或停牌要往前找最近开市日 |
| 补贴收入 | 有旧字段，近年报表常空 | 会计准则改了，多数要看「其他收益」 |

**日线到底能回到哪一年：** 文档只说「不选日期就是全部历史」，没保证回到上市那天。中直若要从 1997 年算「长窗底」，必须用正式证书实测第一根棒的日期。演示证书会假装所有股票都是同一份样本，测了也作不得数。

## 6. 使用上只要记住这几条

1. **证书有调用次数上限（常见是「按自然日」重置，长期池另有规则，见 §6.1）。** 全市场现价那种「一次拉全部」官方写明大约一分钟只能一次。自选几十只通常够用；把指数两千只当「刷新全表」会很快打满。打满后格子会空，不是软件把假数填上。
2. **演示证书不能当实盘。** 它不理你查哪只股票，只给固定样本。软件会挡住，避免你把样本当成全市场。
3. **指数成份 ≠ 该交易所全部。** 深证成指不是深市全部；北证50 不是北交所全部。
4. **北向、新闻、期货价、出口占比** 不要指望靠这次「官网变多了」自动出现。
5. **数字以麦蕊当天为准。** 底和顶是软件算法，换复权方式整张表都会变；现在跟旧表一样按不复权算。

### 6.1 一次 API 请求 ≠ 整张表「全量」，也不等于你点了一次「查询」

很多人会把三件事混在一起，分开记就不容易误判额度：

| 说法 | 对不对 | 人话 |
|---|---|---|
| 向麦蕊发 **一次 HTTP**（一个 URL + 证书） | 一般 **扣 1 次额度** | 和官网「证书当日次数」同一粒度；返回 `101:…已超限` 就是这类额度用完了 |
| 这一次 HTTP 能拿到 **表格里所有列、所有自选** | **不对** | 每个路径只负责一小块：例如 `ssjy` 是现价，`gsjj` 是简介，日线是 K 线，各打各的 |
| 在工作台 **点一次「查询 / 刷新」** | **通常会打很多次 HTTP** | 软件要按你勾选的列，对每只票去拼数据；不是「一次请求打包全表」 |

**一次 HTTP 通常只覆盖：**

- **单只、单类**：如 `/hsrl/ssjy/{6位}` → 这一只的现价相关字段；`/hscp/gsjj/{6位}` → 这一只的简介与概念串。
- **一批现价**：`/hsrl/ssjy_more/{代码1,代码2,…}` → 最多约 **20 只** 一批（本软件拉现价用这个）。
- **全市场名单**：`/hslt/list` → 一次拿到几千只的代码与名称，**不含**每只的财务、股东、离底% 等。

**你点一次自选查询（举例，默认列较多、强制走现网）大致会：**

1. 按列需要，先批量拉现价（每 20 只一批 `ssjy_more`；若开了墙钟且强制现网，还可能多拉自选宇宙里别的代码现价）。
2. 对 **每一只** 再按需调：行业树 `hszg`、简介 `gsjj`、股东、财务、资金流、指标、日线（算离底% 等）——**勾几类就多几轮请求**。
3. 自选 10 只、列全开时，往往是 **几十次** 麦蕊调用，而不是 1 次。

其它也会耗次数：**启动探针**（3 只各 1 次 `ssjy`）、**顶部指数**、**按市场筛选**时的全市场名单、Agent/监控里触发的 `market_fetch` 等。

**省额度习惯：** 少勾用不到的列；不必每次点刷新；有墙钟档口时优先读档；避免反复拉全市场名单。证书在「本机数据 → 麦蕊证书池」维护：**每日刷新池**（当日用尽换下一张、次日恢复）与 **长期池**（总额度用尽后从池里删除）；默认先用每日池再用长期池。状态可看 `/api/health` 里的 `licence_pools`。

### 6.2 一次「刷新」的麦蕊 HTTP 成本（统计）

**统计口径（与当前代码一致，2026-09-22）：**

- 前端点 **「刷新」** = `loadBoard()` + `runQuery(..., force_live=true)`（与「查询」、登录后首次拉表相同：`force_live` 跳过墙钟现价档）。
- 只计发往 **`https://api.mairuiapi.com`** 的 `httpx.get`（扣证书额度）；**不计**本机 `/api/query/run`、`/api/markets/board` 等。
- **列设置**：未改过时用注册表 **默认 32 列**（含离底% 等需日线的列；北向默认不勾）。
- **标的**：沪深 A 股；**冷缓存**（该只日线尚未在 `data/cache/` 命中时每只多 1 次 `history`）。
- **墙钟**：未配置账本目录时，现价只拉当前池内 **N** 只；若已配置且宇宙代码较多，`align_quotes` 可能一次刷新拉 **Q≥N** 只现价（见 §7.5）。
- **顶部指数**：3 个（上证 / 深成 / 科创50），各 **1～4** 次 `hsindex` 试路径，**常见 3 次**。

**每只票（默认列、冷缓存）固定拆法：**

| 数据块 | 次/只（常见） | 次/只（上限） | 麦蕊路径要点 |
|---|---:|---:|---|
| 现价 | 摊分 | 摊分 + 回退 | `ceil(Q/20)` 次 `ssjy_more`；批失败时回退为每只 1 次 `ssjy` |
| 行业 / 概念 / 主营 | 2 | 2 | `hszg/zg` + `hscp/gsjj` |
| 股东 | 2 | 4 | `flowholder` + `topholder`（失败再试 `ltgd` / `sdgd`） |
| 财务 | 3 | 5 | `pershareindex` + `income` + `capital`（`capital` 失败再试 `instrument`） |
| 资金流 | 1 | 1 | `hsstock/history/transaction/{6位}` |
| 日线（底顶） | 1 | 1 | `hsstock/history/.../d/n`；**缓存命中则为 0** |

记 **Q** = 本次 `align_quotes` 实际拉现价的代码数（通常 **Q = N**），**冷缓存**时：

```text
查询 HTTP ≈ ceil(Q / 20) + N × 9
刷新合计 ≈ 查询 HTTP + 3   （指数，常见路径一次命中）
```

**日线已缓存**时把上式里的 `9` 改成 `8`（每只少 1 次 `history`）。

| 自选 N（Q=N） | 查询（冷缓存） | 一次刷新合计（+3 指数） | 日线已缓存时查询 |
|---:|---:|---:|---:|
| 1 | 10 | 13 | 9 |
| 10 | 91 | **94** | 81 |
| 20 | 181 | 184 | 161 |
| 40 | 362 | 365 | 322 |

上表 **N=10 冷缓存 91 次** 与仓库脚本 `scripts/count_refresh_http.py`（Mock 成功路径、无墙钟）**实测一致**；刷新 **94 次** = 91 + 3 指数。

**不含在本次「刷新」里、但容易混淆的：**

- 启动时 **探针** 3 次 `ssjy`（仅进程初始化 / 池恢复时，不是每次点刷新都打）。
- 换 **指数池 / 全市场名单**、勾 **X 日价**、开 **3/5/10 日指标列**、北交所标的、Agent 工具链等，次数在上式基础上 **另加**。
- `ssjy_more` 整批失败时，现价可能变成 **N 次** 单只 `ssjy`，查询次数可接近 `ceil(Q/20) + N×9` 再加 **N**（最坏）。

### 6.3 查询表：每一列会不会单独打一次 HTTP？

**不会。** `QueryEngine`（`src/query/engine.py`）先根据**勾选列**合并出依赖集合 `need`（来自 `src/query/registry.py` 里每列的 `requires`）。同一依赖块内**多列共用同一批请求**；决策卡列来自本地 DB，不占麦蕊。

| 列 key / 中文名 | 依赖块 | 单独为这一列打 HTTP？ | 说明 |
|---|---|---|---|
| `name` / `code` 名称、代码 | — | **否，0 次** | 自选 / 池名单（本地） |
| `price` `pct` `pe` `pb` `turnover` `mcap` `fcap` `pct60` `pct_ytd` 现价相关 | `quote` | **否，共用** | 全表 `ceil(Q/20)` 次 `ssjy_more`（或回退单只 `ssjy`） |
| `pct3` `pct5` `pct10` 短周期涨幅 | `indicators` | **否，共用** | 每只 1 次 `hsstock/indicators` |
| `industry` `sector` `sw_l1` `hot_concepts` `concept` `business` 行业概念主营 | `profile` | **否，共用** | 每只 2 次：`hszg/zg` + `gsjj`；七大板块 / 申万 / 2026 概念多在本地 `taxonomy` 上归类 |
| `holders` `top_holders` 股东 | `holders` | **否，共用** | 每只 2～4 次（流通 + 十大，失败换备用路径） |
| `zgb` `ltgb` `mgwfplr` `yffy` `mgjzc` `eps` `gross` `net` 财务 | `finance` | **否，共用** | 每只 3～5 次 |
| `flow_in` `flow_out` `flow_net` 资金 | `flow` | **否，共用** | 每只 1 次 `history/transaction` |
| `northbound` 北向 | — | **否，0 次** | 列定义不可用，不打麦蕊 |
| `x_price` X 日价 | `bars` | 与底顶共用日线 | 每只 0～1 次 `history` |
| `low1y` `low_long` `high` `off_low` `multiple` `target` `low_note` 底顶 | `quote` + `bars` | **否** | 一次 `history` + 本地 `compute_bottom` 填多列 |
| `buy_low` `buy_high` `reduce_at` `cost` `thesis` 决策卡 | `card`（本地） | **否，0 次** | `WatchItem` 决策卡 |
| `vs_cost` `dist_buy` `dist_reduce` 相对成本/距买区/距减仓 | `quote` 或 `quote`+`bars` | **否** | 用已有现价（及底）本地算，不新增路径 |

**粒度三层（避免和「列」混淆）：**

```text
用户点一次「刷新」 → 1 次本机 /api/query/run（不计麦蕊额度）
                 → 若干「依赖块」× 每只票（或整池一批现价）
                 → 每次 MarketClient._get → 通常 1 次麦蕊 HTTP
```

### 6.4 全量刷新里，次数主要耗在什么上？

在 **默认 32 列、沪深、`force_live`、冷缓存** 下，查询次数近似 `ceil(Q/20) + 9N`（§6.2）。**贵的不是「列多」，而是默认勾上了 profile + holders + finance + flow + bars 五类慢字段**；现价批只占极小比例。

**N = 10 只时，查询约 91 次 HTTP 的构成：**

| 依赖块 | 用途 | 次数（N=10） | 占查询比例 |
|---|---|---:|---:|
| **finance** | 每股指标、利润表、股本 | 30 | **~33%** |
| **profile** | 行业树、简介/概念 | 20 | **~22%** |
| **holders** | 流通股东、十大股东 | 20 | **~22%** |
| **flow** | 资金流向 | 10 | ~11% |
| **bars** | 日线 → 底顶离底等 | 10 | ~11% |
| **quote** | `ssjy_more` 批量现价 | 1 | **~1%** |

N 变大时，上述五块按 **9N** 线性涨；只有 **quote** 项是 **⌈N/20⌉**。顶部指数再 **+3** 次左右，相对全表仍很小。

**麦蕊侧几乎不能靠「合并 HTTP」再压慢字段**：除 `ssjy_more`（≤20 码）和套餐级 `ssjy/all`（全市场、强限频）外，财务 / 股东 / 简介 / 日线等**没有官方「多股一包」接口**；省额度要靠**少勾依赖、缓存、分「快刷现价」与「慢字段全量」**，见 §6.5。

### 6.5 现网问题归纳（与额度、刷新行为）

以下来自 2026-09 现网排障与实现对照，说明「为什么容易空表、为什么一万次/日不够随便点刷新」。

| 现象 | 根因（代码 / 配置） | 和请求次数的关系 |
|---|---|---|
| 登录后表全 `—`、指数 0.00 | 证书 **101 当日超限** 或池内无证可用；`_get` 全部失败 | 不是没发请求，是**请求都失败**；`/api/health` 看 `licence_pools`、curl 单只 `ssjy` 可验证 |
| 提示「演示样本」但并非演示证 | 旧版探针在三次 `ssjy` **全失败**时误判 `sample_only`（已改为 `probe-failed`） | 误导方向；真因仍是额度或网络 |
| 点一次「刷新」很费次数 | 刷新 = `force_live` + **默认全列** → 每只约 **9 次**慢接口 + 批现价；**不读**墙钟现价档 | 与 §6.4 一致；**finance + profile + holders** 占约 **77%** |
| 没有「上次全量副本」可复用 | 无服务端 query 快照；仅 `data/cache` **分项**缓存（日线、名单等）；墙钟只缓存**现价**档口 | 每次刷新仍会对慢字段**重复打满**（除非 cache 命中） |
| 有墙钟目录仍狂拉现价 | `force_live=true` 跳过档口读盘；且可能按宇宙 **Q>N** 扩码拉 `ssjy_more` | Q 大时现价次数也上去 |
| `.env` 与池子两套证 | 每日刷新池 + 长期池（`licence_registry.json`）；用尽后轮换或删除 | 两池都尽则与「没证」相同 |
| 一万次/日证书 | N=10 全量刷新约 **94 次/次** → 一天只能 **~100 次**量级全量刷新 | 必须拆分「快刷」与「慢字段更新」或 TTL |

**改进方向：**

1. **P0（已实现）**：工作台 **「刷新」** = `refresh_mode=quote`、默认不 `force_live`、快刷不扩墙钟宇宙；**「查询 / 全量更新」** = `refresh_mode=full` + `force_live`；快刷时前端合并保留已有慢字段列。API：`POST /query/run` 字段 `refresh_mode`: `quote` | `full`（默认 `full` 兼容旧调用）。
2. **P1（已实现）**：列预设「看盘 / 研究 / 自定义」；新用户默认 **看盘**（`name,code,price,pct,pe,pb`）。`GET/PUT /query/prefs` 含 `preset` 与 `presets` 目录；升级前已保存完整列清单的用户仍按原列查询（`preset=watch` 且 `field_keys` 与看盘不一致时视为自定义列集）。
3. **P2（已实现）**：`data/cache/` 分项 TTL（profile/holders/finance 默认 24h，flow/indicators 默认 1h；`.env` 可配 `SLOW_CACHE_*_TTL_SEC`）。`refresh_mode=cache` 时慢字段未过期则不打麦蕊；日线仍用既有 `bars_*` 冷缓存。工作台 **「查询」** = `cache` + 不 `force_live`；**「全量更新」** = `full` + `force_live`；响应可含 `slow_cache: {hits, misses}`。
4. **P3（已实现）**：`data/snapshots/user_{id}.json` 表级快照；`cache`/`full` 成功后写入。`refresh_mode=snapshot` **零麦蕊**，只读上次快照（决策卡列仍按 DB 重算）。登录先 `snapshot` 再 `cache`；**刷新**不再顺带拉顶栏指数（指数本地 60s 缓存）。监控 `engine.run` 与 Agent `query_run`、资讯监控 `profile` 默认走 `cache` 慢字段 TTL。`GET /storage` 含 `query_snapshot` 元数据。
5. **行为**：非必要不用 `force_live`（快刷已遵守）；导出 Excel 固定走全量。
6. **运维**：本机数据 → 麦蕊证书池；避免 101 状态下反复点全量更新。
7. **监控 / Agent 日额度**：一万次/日证下如何分区、调 session/eod 频率与任务开关，见 [`监控与麦蕊额度预算.md`](./监控与麦蕊额度预算.md)。
