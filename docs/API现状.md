## 0. 一句话结论

现有表格里的**原始数据列**（行情、市值、财务、分红、补贴收入、X日价）API 全部能取到；但表格的**核心逻辑列**——「底 / 顶 / 离底% / 高底% / 倍数 / 目标卖价」这一整套——API **不直接提供，必须自己算**，好在算它们所需的全历史日线数据 API 是给的。

股东股本、前十大流通股东数据**都有**，而且有两套接口可选。

初版遗留的两个「未识别列」现已全部查清（见 §3），且两列 API 均直接支持，**表格中不存在 API 覆盖不到的原始字段**。

⚠️ **唯一的硬前提：** 标准 `hsstock/history` 的历史回溯深度**在文档中从未定义**（见 §4.5）。「17年后底」是否可行完全取决于此，必须先实测再动工。

## 2. 查不到 / 必须自己算的信息

现有表格的核心列全部落在这一区。API 没有任何「N年最高/最低价」类字段，也没有任何估值目标价字段。

| 表格中的列 | API 状态 | 计算方式 | 所需原料 |
|---|---|---|---|
| **底 / low**（近1年底、17年后底） | ❌ 无 | 区间 `min(l)` | `hsstock/history` 日线 |
| **顶** | ❌ 无 | 区间 `max(h)` | 同上 |
| **离底%** | ❌ 无 | `(现价 - 底) / 底` | 现价 + 上面算出的底 |
| **离1年底%** | ❌ 无 | 同上，区间取近1年 | 同上 |
| **高底%** | ❌ 无 | `(顶 - 底) / 底` 或 `现价/顶` 类比值 | 顶 + 底 |
| **底一贯 / 层一贯（倍）** | ❌ 无 | 顶底倍数 `顶 / 底` | 顶 + 底 |
| **目标卖价**（表头注明「底涨50%」） | ❌ 无 | `底 × 1.5` | 底 |
| **比价差%** | ❌ 无 | `(目标卖价 - 现价) / 现价` | 现价 + 目标卖价 |
| **比日涨跌%** | ❌ 无 | 自定义对比口径 | 实时 `pc` |

**可行性结论：全部可算，但有一个前提待实测。** `hsstock/history` 不传 `st`/`et` 时返回「全部历史数据」——原文用词就是这四个字，**并未定义历史深度**。「日线以上为上市以后所有数据」这句话在原文中**只出现在企业版接口的说明里**，不能想当然套用到标准接口上。

> ⚠️ **「17年后底」这一列的可行性，完全取决于标准 `hsstock/history` 的实际回溯深度。这是整套方案唯一的硬前提，必须第一步就实测验证**（详见 §4.5）。

**⚠️ 口径必须先定：** 该接口支持 5 种复权方式。从截图数据推断（中直股份 底 24.6 / 现价 26.86），现有表格用的是**不复权 `n`**。若改用复权价，所有底/顶/倍数结果都会变，需保持全表一致。

**部分可省力：** 3日/5日/10日涨幅与换手可直接取 `hsstock/indicators`；60日涨跌幅、年初至今涨跌幅可直接取 `hsrl/ssjy` 的 `zdf60` / `zdfnc`，不必自算。

## 3. 曾未识别的列（已全部解决 ✅）

初版文档中有两列表头因图片压缩而误读。放大原图后两列均已确认，且**两列 API 都能直接支持**。

| 位置 | 初版误读 | 实际表头 | API 状态 |
|---|---|---|---|
| 图1 倒数第3列 | ~~补股收入~~ | **补贴收入** | ✅ 利润表 `btsr` |
| 图2 最左列 | ~~3 日价~~ | **X 日价**（X 为可输入日期） | ✅ 日线 `history` 指定日期 |

### 3.1 补贴收入 → `btsr`

表头因列宽过窄被折行显示成「补贴收 / 入」两行，初版误读为「补股收入」。

`hsstock/financial/income`（利润表）中有现成字段：

```
btsr    float    补贴收入
qtsy    float    其他收益
```

**为什么整列都是 `–`：** 这不是 API 缺数据，而是会计准则变更所致。2017 年财政部修订《企业会计准则第 16 号——政府补助》后，与日常经营活动相关的政府补助不再计入「补贴收入」，改列报于「**其他收益**」。因此近年报表中 `btsr` 基本恒为空，真实数据落在 `qtsy` 上。

**✅ 已实测证实**（`hsstock/financial/income/000001.SZ`，2025 年三期）：

| 截止日期 | `btsr` 补贴收入 | `qtsy` 其他收益 |
|---|---|---|
| 2025-09-30 | 空 | 56,000,000 |
| 2025-06-30 | 空 | 50,000,000 |
| 2025-03-31 | 空 | 43,000,000 |

> ⚠️ 该接口对空值返回的**不是 JSON `null`，而是字符串 `"-"`**，判空逻辑必须同时处理 `null` / `""` / `"-"`（脚本中的 `Test-Blank` 即为此）。

> **建议：** 取数时用 `qtsy`（其他收益），或 `btsr` 为空时回退到 `qtsy`。若坚持照搬原表口径，则该列在现行准则下本就应为空。

### 3.2 X 日价 → 指定日期收盘价

这一列不是固定指标，而是一个**带日期参数的查询列**：表头下方 `20260305` 是输入框，填什么日期，整列就显示各股在该日的收盘价。

反推验证（20260305 = 2026年3月5日）：

| 代码 | 名称 | X日价 | 底 | 现价 | 顶 |
|---|---|---|---|---|---|
| 600038 | 中直股份 | 37.05 | 24.6 | 26.86 | 80.45 |
| 000725 | 京东方A | 4.46 | 2 | 5.78 | 9.1 |
| 002230 | 科大讯飞 | 52.19 | 16.55 | 41.25 | 80.4 |
| 000988 | 华工科技 | 106.61 | 9.43 | 107.85 | 184.61 |

全部 40 行的 X日价均落在各自 `[底, 顶]` 区间内、且与现价同量级，可确认为历史某日价格而非目标价或均价。

**取数方式：**

```
GET hsstock/history/{code}.{市场}/d/{复权}/{licence}?st=20260305&et=20260305
→ 取返回记录的 c（收盘价）
```

> **两个注意点：**
> 1. 若指定日为非交易日或该股停牌（`sf=1`），该日无数据，需回退到最近一个有效交易日。
> 2. 复权口径要与「底/顶」保持一致（见 §2），否则同一行内的价格不可比。

**顺带一提：** 这一列既然已经从日线缓存里取，就无需额外调接口——§5 第 2 步的本地日线缓存可以直接支撑任意「X 日价」查询，且切换日期时零 API 消耗。

### 4.1 ✅ 属实 — `ZygdSdgd` 对象未定义

`hscp/sdgd`（十大股东，第 528 行）和 `hscp/ltgd`（十大流通股东，第 539 行）的核心字段 `sdgd` 标注为 `array<ZygdSdgd>`，说明栏写「见下方说明」。全文检索 `ZygdSdgd` **仅这 2 处引用，无任何定义**；且文档无图片，排除图示可能。

**✅ 实测已补齐该对象结构**（请求 `hscp/sdgd/000001`，内层数组 10 个元素）：

| 字段 | 含义 | 示例值 |
|---|---|---|
| `Pm` | 持股排名 | `1` |
| `Gdmc` | 股东名称 | `中国平安保险(集团)股份有限公司-集团本级-自有资金` |
| `Cgsl` | 持股数量（股） | `9618540236` |
| `Cgbl` | 持股比例（%） | `49.56` |
| `Gbxz` | 股本性质 | `流通A股` |

> ⚠️ 注意这 5 个字段**首字母大写**，与全站其他接口的全小写命名风格不一致，反序列化时容易踩坑。
>
> **应对：** 仍优先使用 `hsstock/financial/topholder` 和 `flowholder`——字段平铺、定义完整、支持时间区间。`hscp/sdgd` 的优势是额外带 `gdzs`（股东总数）与 `pjcg`（平均持股）。

### 4.2 ⚠️ 部分修正 — 限频

**数值属实**，但**性质需要修正**：全文 74 个接口的「频率」字符串**完全一致**（74/74 逐字相同），说明它是**批量填充的模板文本，不区分接口，不具备参考价值**。

| 版本 | 模板标称频率 |
|---|---|
| 普通 | 1分钟 300 次 |
| 包月版 / 体验版 | 1分钟 1000 次 |
| 包年版 | 1分钟 3000 次 |
| 钻石版 | 1分钟 6000 次 |

**证据：** `a.mairuiapi.com/hsrl/ssjy/all`（第 649-650 行）和 `hsrl/real/all`（第 697-698 行）的「频率」栏同样写着「钻石版1分钟6千次」，但紧邻的「说明」栏明确写着「**仅限钻石版和包年版证书使用且限制每分钟请求 1 次**」——同一接口自相矛盾。

> **结论：以「说明」栏为准，「频率」栏一律不可信。**

**❌ 初版应对措施不成立：** 初版写「几千只股票必须做本地缓存」，这是我的臆测。实际截图中的股票池**只有 40 只**（600038…603395），按 40 只算，全量拉取 17 年日线仅需 **40 次请求**，即便最低档 300 次/分钟也毫无压力。**限频对当前场景基本不构成约束**。仅当日后扩展到全市场（约 5000 只）时才需要考虑缓存与限速。

补充：`hsrl/ssjy_more` 支持一次查最多 20 只（第 673 行），可用于中等规模批量。

### 4.3 ✅ 属实（但影响被高估）

四个市场确为**分开的四套接口**：沪深 `hslt/list`、北交所 `bj/list/all`、科创 `kc/list/all`、基金 `fd/list/all`。

**实际情况比初版描述更严重：** 京市和科创不只是缺财务与股东数据，**连历史 K 线接口都没有**——
- 京市全部接口仅 5 个：股票列表、指数列表、股票实时、五档盘口、指数实时
- 科创全部接口仅 3 个：股票列表、股票实时、五档盘口

这意味着**这两个市场连「底/顶」都算不出来**（无历史数据源）。

**❌ 但初版高估了实际影响：** 截图 40 只代码中**没有任何 688xxx（科创）或 8xxxxx/4xxxxx（北交所）标的**，全部是沪深主板、中小板、创业板。**对当前表格不构成任何影响**，仅在日后扩池时需注意。

### 4.4 ✅ 全部属实 — 数据更新时点

逐条核对无误，另补齐初版遗漏的两项：

| 数据类型 | 更新时间 |
|---|---|
| 股票/指数列表 | 每日 16:20 |
| 新股日历 | 每日 17:00 |
| 实时行情 | 盘中实时（网络源为每 1 分钟） |
| 日线及以上K线 | 每日 15:30 开始，约 17:10 完成 |
| 技术指标（日线级 MACD/MA/BOLL/KDJ） | 每日 15:35 |
| 行情指标（`indicators`） | 每日 16:30 开始，约 20:00 完成 |
| 当天逐笔交易 | 每日 21:00 |
| 资金流向 | 每日 21:30 |
| 财务报表 / 股东股本（`hsstock/financial/*`） | 每日 0:00 |
| 股票基础信息（`instrument`） | 每日 1:00 |
| 公司资料（`hscp` 系列） | 每日 3:30 |
| 基金持股 | 每周六 18:00 |
| 概念/行业树 | 每周六 3:05 / 11:00 |

> **「20:00 之后刷新」的结论成立。** 本表所需字段中更新最晚的是「行情指标」（约 20:00 完成）。若日后加入资金流向列，需顺延至 21:30 之后。

### 4.5 ❌ 初版有误 — 历史回溯深度**未文档化**

**初版原文：**「标准版 `hsstock/history`……分钟级历史仅保留最近 3 年，日线以上才是上市以来全部。」

**错在哪：** 「分钟级历史数据为最近 3 年以内，日线以上为上市以后所有数据」这句话在全文中**只出现一次，位于第 875 行——企业版专属接口 `hsstock/vip` 的说明里**。我把它错误地套用到了标准接口上。

**标准 `hsstock/history`（第 829 行）的原文只说：**「不设置开始时间和结束时间则为**全部历史数据**」——**没有定义任何深度、也没有承诺回溯到上市日**。

**为什么这条最要命：** §2 中「17年后底可算」这一整套核心逻辑，正是建立在这个未经证实的假设上。若标准接口实际只回溯 3–5 年，则表格中「17年后底」「顶」「层一贯倍数」「目标卖价」**全部失效**。

> **必须实测（列为第一优先级）：**
> ```
> GET hsstock/history/600038.SH/d/n/{licence}
> ```
> 不带 `st`/`et`，检查返回的首条 `t` 是哪一年。中直股份 1997 年上市，若首条能回到 1997 或至少 2009 年之前，则方案成立。
>
> **若回溯不足：** 备选方案是用 `st=20090101` 显式指定起始日再试（部分 API 不传参时只返回近期数据，显式传参反而能取到更早数据）；仍不足则需考虑企业版或更换历史数据源。

**该条中属实的部分：** 标准 `hsstock/history` 最小粒度确为 5 分钟；1 分钟级确需企业版（专属子域名，第 873 行）。

### 4.6 🆕 新增 — 代码参数格式在同一接口族内不统一

这是最容易踩的实现坑。**不能简单记成「`hsstock` 用后缀、其他不用」**，因为 `hsstock` 族内部就不一致：

| 需带 `.市场` 后缀（如 `000001.SZ`） | 只要 6 位纯代码（如 `000001`） |
|---|---|
| `hsstock/latest`、`hsstock/history` | `hsstock/real/time`、`hsstock/real/five` |
| `hsstock/stopprice/history`、`hsstock/indicators` | `hsstock/history/transaction` ⚠️ |
| `hsstock/instrument`、`hsstock/financial/*` | `hscp/*` 全部、`hsrl/*` 全部 |
| `hsstock/history/{macd,ma,boll,kdj}` | `bj/*`、`kc/*`、`fd/*` 全部 |

⚠️ 特别注意 `hsstock/history/transaction`（资金流向）——它在 `hsstock/history/` 路径下，却是**纯代码**，与同前缀的 `hsstock/history/macd` 等相反。

**⚠️ 实测后结论反转——文档对 `hslt/list` 返回值的描述是错的：**

| 字段 | 文档描述 | **实测真实值** |
|---|---|---|
| `dm` | `000001`（纯 6 位） | **`000001.SZ`（已带后缀）** |
| `jys` | `"sh"` / `"sz"`（小写） | **`"SZ"`（大写）** |

也就是说：调用 `hsstock/*` 时**无需拼接后缀，直接用 `dm` 即可**；反而调用 `hscp/*`、`hsrl/*`、`bj/*`、`kc/*`、`fd/*` 时需要**主动把后缀去掉**。这与初版给出的建议正好相反。

> **应对：** 在数据层统一封装 `code6()`（截断到 6 位）和 `codeFull()`（直接用 `dm`），按接口查表决定用哪个，不要在调用处手写。
>
> ⛔ 各接口究竟接受哪种写法，需用正式 licence 跑 `Verify-Api.ps1` 的 T2 项确认（演示 licence 忽略代码参数，测不出来）。

### 4.7 🆕 新增 — 单次返回条数上限未知

17 年日线约 4100 条。文档**从未说明**单次响应是否有条数上限或分页机制，只说了 `lt` 可以限制条数（取最新 N 条）。存在静默截断的风险。

> **应对：** 与 4.5 一并实测——拉全量后核对返回条数与预期交易日数是否吻合。若被截断，改为按年分段拉取（`st`/`et` 逐年切片）再本地拼接。

### 4.8 ✅ 已实测确认 — `hslt/list` 的覆盖范围

文档只说「获取基础的股票代码和名称」，未说明范围。**实测结果（2026-09-02，共 5203 条）：**

| 板块 | 数量 |
|---|---|
| 000/001 深主板 | 529 |
| 002/003 中小板 | 963 |
| 300/301 创业板 | 1397 |
| 600/601/603/605 沪主板 | 1704 |
| **688/689 科创板** | **609** |
| 4xx/8xx 北交所 | **0** |
| **合计** | **5203** |

> **结论：`hslt/list` 已涵盖科创板**（609 只），**无需**另调 `kc/list/all`——这同时削弱了 §4.3 关于科创板的担忧（科创标的能否走 `hsstock/history` 仍待正式 licence 验证）。

> **北交所确实不在内**，需另走 `bj/list/all`，且该市场无历史数据接口。

### 4.9 🆕 新增 — 文档自身的笔误（照抄会出错）

| 位置 | 问题 |
|---|---|
| `hsstock/real/time`、`hsstock/real/five`、`hsindex/real/time` | 地址模板写成 `/证书您的licence`，多出「证书」二字。**✅ 已实测证实为笔误**：传 `/{licence}` 可用，传 `/证书{licence}` 报错 |
| `hsindex/latest`、`hsindex/history` | 演示 URL 用 `000001.SZ`，但上证指数应为 `000001.SH`，**演示写错了市场后缀** |
| `hsindex/history/kdj` | 地址模板无「除权方式」参数，演示 URL 却是 `000001.SH/n/LICENCE`，多传了一个 `n` |
| `hsindex/real/time` | 模板写 `指数代码(如：000001.SH)`，演示 URL 却用 `000001`（无后缀），**模板与演示互相矛盾** |
| `hslt/ztgc`（涨停股池） | 返回字段中 `hy`（所属行业）**连续重复列出 6 次**（第 137–142 行），显系复制粘贴错误，实际字段数存疑 |

> **应对：** 凡模板与演示 URL 冲突处，**以演示 URL 为准**（演示是可直接跑通的真实链接）。

## 5. 落地建议（顺序）

> **第 0 步是前置校验，不通过则后续方案需重新设计。**

0. **【必做】取得正式 licence 后运行验证脚本**：

   ```powershell
   .\scripts\Verify-Api.ps1 -Licence "你的licence"
   ```

   重点看报告中的 **T3+T4（历史回溯深度）**——这一步决定「17年后底」整套逻辑是否成立（见 §4.5、§4.7）。同时会一并验证 T2 代码参数格式、T9 跨市场支持。
   
   ⚠️ 用演示 licence 跑没有意义：它忽略股票代码、只返回固定样本，脚本会自动识别并标记 ⛔。
1. 用 `hslt/list` 建立股票池，落库；`dm` 本身已带后缀（如 `000001.SZ`），调 `hscp/*`、`hsrl/*` 时需截断为 6 位（见 §4.6）。
2. 用 `hsstock/history`（日线、不复权、全历史）**一次性全量抓取并本地缓存**，此后每日增量追加。当前池仅 40 只，无限频压力。
3. 在本地基于日线缓存计算：底、顶、离底%、离1年底%、高底%、倍数、目标卖价、比价差%。
4. 用 `hsrl/real/all`（或分批 `ssjy_more`）刷新实时列：现价、涨跌%、换手%、市值、PE、市净率。
5. 用 `hsstock/financial/pershareindex` + `income` 补财务列：净资/股、每股未分配利润、营业总收入、研发费用、补贴收入（`btsr`，为空则回退 `qtsy`）。
6. 用 `hscp/jnfh` 补分红列（每10股派$，返回历年数组）。
7. 用 `hsstock/financial/topholder` / `flowholder` / `capital` / `hm` 补股东股本模块。
8. 「X 日价」直接查第 2 步的本地日线缓存，无需额外调接口；注意非交易日/停牌回退。
