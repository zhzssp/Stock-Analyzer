## 2. 可靠性边界（为什么不能当依据）

| 问题 | 具体表现 |
|---|---|
| **超短别名误伤** | 别名 `AI` 只有两个字母，概念文字里任何 "AI" 片段都会命中「人工智能」。这是最典型的一类假阳性 |
| **宽泛别名误伤** | 「卫星」→ 做导航地图的也被标「商业航天」；「液冷」→ 做机房空调配件的被标「人工智能」 |
| **漏配** | 公司确实做 AI，但上游文字写的是「机器学习 / 深度学习 / 神经网络」→ 一个别名都不命中 → 该列空着 |
| **依赖上游文字** | `hay` 完全来自麦蕊返回的行业/概念文本。它写得短、旧或为空，本地就算不出东西 |
| **链式错误** | 申万一级错 → 七大板块跟着错，没有交叉校验 |
| **无权重** | 做主业的与只沾边的，标签完全一样，看不出主次 |
| **人工维护** | 标签与别名是写死的，新热点（如固态电池）不加就永远命中不了 |

定性：**能"猜个大概"，可用于粗筛，不能用于判断"这家公司到底属于什么概念"。**

## 3. 为什么只能这么做（不是偷懒）

麦蕊**没有提供「某只股票属于哪些官方概念」的接口**：

- `hsindex/constituent` → 404
- `hszg/list` + `hszg/gg/{节点}` 能取成份，但**只覆盖官方概念树里存在的节点**；「2026概念」是我们自己定义的标签集合，官方树里未必有同名节点
- 已做过的补救：筛选弹窗点 2026 概念时，**官方树里有该节点的走 API 取官方成份**（比表上那列可靠），树里没有的才退回关键词。见 R-20260921 U7（一期已接）

所以：点概念芯片筛出来的票，比表上「2026概念」这一列更可信；两者不一致时以官方成份为准。

## 4. 关闭条件（三档，任选其一才算处理过）

1. **接官方概念树建映射表（正解，关闭本条）**
   `hszg/list` 拉全部概念节点 → 逐个 `hszg/gg/{节点}` 取成份 → 本机建「股票 → 官方概念」表，每日刷新一次；表上 `sector` / `sw_l1` / `hot_concepts` 改为查这张表。代价：初次建表数百次请求（可缓存、一天一次），且需把官方概念名与 2026 标签做一次映射。
2. **给匹配加约束（止血，不关闭本条）**
   `AI` 这类超短别名改成全词匹配（避免英文片段命中）；区分"主营命中 / 沾边命中"并在表上可辨。
3. **透明化（必须做，无论是否做 1）**
   列设置里给这三列标注「本地推断」，`?` 帮助里写明"由行业/概念文字匹配得出，可能漏配误配"，避免被当成权威数据对外使用。

**不做的事（关闭前禁止）：**

- 不要把本地推断的板块/概念当作"数据商官方分类"写进对客说明或对外讲解
- 不要为了让表好看而放宽别名（会让误伤更多）
- 不要静默把关键词命中的结果改称"官方成份"
