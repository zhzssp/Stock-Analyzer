## 0. 一句话

这不是一个「什么都会的问答机器人」，而是一套**智能体系统**：

- 底下是共用的**平台内核**（股票池、行情/日线缓存、插件、事件总线）。
- 上面挂**彼此独立的智能体**。每个智能体只做一类事，可以单独开关、单独进化。
- 智能体内部的具体能力（算哪几列、用哪条规则、往哪推）再做成**插件**。

现有表格是分析智能体的第一批插件；定时盯盘并推送「有价值」标的，是第二个独立智能体的第一版形态。两者共享数据，不共享大脑。

---

## 1. 为什么必须是系统，而不是一个智能体

把「查表问答」和「定时扫描推送」塞进同一个智能体，短期能跑，后面会焊死：

| 混在一起的后果 | 拆开之后 |
|---|---|
| 问答要等扫描跑完，扫描要迁就对话上下文 | 各有生命周期：一个等人问，一个按钟走 |
| 规则、列、话术缠在同一套 prompt / 同一份代码 | 规则属于盯盘智能体；列和解释属于分析智能体 |
| 想加「复盘智能体」「研报摘要智能体」只能继续膨胀 | 新智能体挂上总线即可，不必改旧的 |
| 推送失败会拖垮查数；查数改口径会误触发推送 | 故障隔离：一个挂了，另一个仍可用 |

所以扩展有两条正交的轴：

```
加一种「谁在工作」  →  注册一个新智能体
加一种「它会干什么」→  给某个智能体加插件
```

问答只是分析智能体的一种入口，不是整个系统的形态。

## 2. 目标与非目标

### 2.1 要解决什么

1. **同一批自选股，每天要扫固定口径**（现价、离底、目标卖价、财务、股东）。
2. **口径写死在表里就没法长**——加列、加规则、加推送渠道都不能改整张表。
3. **底 / 顶 / 倍数必须本地算**，API 不直接给，要缓存日线。
4. **人不能一直盯盘**：系统应按事先写好的规则，定时取数、比对变化、把值得看的标的推出来。
5. **后面一定还会出现第三、第四个智能体**（复盘、题材、资金流……），现在就要把「智能体」当成一等公民。

### 2.2 明确不做（至少第一年不做）

- 不下单、不接券商交易接口、不自动买卖。
- 不承诺「荐股」或收益；推送的是「规则命中」，不是投资建议。
- 不先做全市场 5000 只的高频扫描；默认工作集是自选池（约 40 只）。全市场扫描可以作为盯盘智能体的可选插件。
- 不把业务公式写进平台内核，也不写进某个「总智能体」的 prompt。
- 不把多个智能体合成一个超级 agent 再靠 prompt 路由——路由是显式的，不是让模型自己猜该谁干活。

### 2.3 来自 API 的硬约束

| 约束 | 对系统的影响 |
|---|---|
| 日线历史深度未用正式 licence 实测 | 「17 年后底」必须能降级；盯盘规则不能假设一定有 17 年 |
| `dm` 实测已带后缀（`000001.SZ`） | 平台统一 `code6` / `codeFull`，智能体和插件都不拼码 |
| 不同接口族要的代码格式不一致 | 只有 `MarketClient` 碰 URL |
| 演示 licence 返回固定样本 | 写入缓存前必须过真实性门禁 |
| 财务空值可能是 `"-"` | 适配层统一 `blank` |
| 北交所无历史/财务 | 插件声明市场能力；不满足则该行空，不拖垮系统 |
| 复权 5 种 | 日线按 `(code, freq, adjust)` 分桶 |
| 数据更新有墙钟（日线约 17:10，指标约 20:00） | 盯盘智能体的日程必须对齐这些时点，不能想当然「收盘立刻算」 |

## 3. 系统总览

```
                    ┌──────────── 用户 ────────────┐
                    │ 表 / 问答 / 推送接收         │
                    └─────────────┬────────────────┘
                                  │
┌─────────────────────────────────▼─────────────────────────────────┐
│  智能体运行时  AgentRuntime                                        │
│  · 注册表：哪些智能体启用                                          │
│  · 调度：谁按钟跑、谁等人、谁被事件叫醒                             │
│  · 邮箱：AgentMessage 总线（请求 / 结果 / 告警）                    │
└───────┬─────────────────┬─────────────────┬───────────────────────┘
        │                 │                 │
        ▼                 ▼                 ▼
 ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
 │ Analyst     │   │ Watcher     │   │ （预留槽）   │
 │ 分析智能体   │   │ 盯盘智能体   │   │ Reviewer …  │
 │ 表 + 问答    │   │ 定时+规则+推 │   │ 以后再挂    │
 └──────┬──────┘   └──────┬──────┘   └──────┬──────┘
        │                 │                 │
        └────────────┬────┴─────────────────┘
                     ▼
        ┌────────────────────────────┐
        │  平台内核 Platform           │
        │  Universe / MarketClient     │
        │  BarStore / QuoteCache       │
        │  FundCache / ResultStore     │
        │  PluginRegistry / Notifier   │
        └─────────────┬────────────────┘
                      ▼
                   麦蕊 API
```

**平台是仓库，智能体是工人，插件是工人手里的工具。**

- 分析智能体**读** `ResultStore`，按需触发计算，回答人和填表。
- 盯盘智能体**定时写**缓存、跑规则、往总线发 `WatchHit`，再由 `Notifier` 推给人。
- 以后的复盘智能体可以订阅「每个交易日结束后的快照」，不必知道盯盘怎么推送。

两个智能体都可以关。关掉盯盘，表和问答还在；关掉分析，定时推送还在。

## 4. 智能体契约

加智能体 = 实现这份契约 + 在运行时清单里打开。不改平台，不改其它智能体。

### 4.1 清单

```yaml
id: watcher
name: 盯盘智能体
version: 0.1.0
enabled: true
mode: scheduled          # scheduled | interactive | event
schedule:
  - { id: session-tick,  cron: "*/5 9-15 * * 1-5",  tz: Asia/Shanghai }
  - { id: eod-scan,      cron: "20 20 * * 1-5",     tz: Asia/Shanghai }
subscribes: [data.ready, universe.changed]
publishes:  [watch.hit, watch.digest]
uses_plugins: [quote-basic, bottom-value, near-target, near-bottom]
```

`uses_plugins` 声明它依赖哪些能力插件。插件仍是平台级的（一份计算，多方使用），但**谁在何时调用**由智能体决定。

### 4.2 运行时接口（概念）

```
on_start(runtime)              注册日程、订阅事件
on_tick(job_id, ctx)           到点：取数 → 算字段 → 跑规则 → 发布命中
on_message(msg, ctx)           被其它智能体或用户叫醒
on_stop()                      收尾
```

`ctx` 与插件共用同一套数据内核，另加：

- `publish(topic, payload)` / `inbox`
- `now` / `is_trading_day`
- 本智能体的规则集与推送策略

智能体**禁止**直接调麦蕊 HTTP，也**禁止**改另一个智能体的内部状态。要协作，只发 `AgentMessage`。

### 4.3 总线上的消息（先定这几条，以后再加）

| 主题 | 谁发 | 谁收 | 含义 |
|---|---|---|---|
| `data.ready` | 平台或盯盘在刷新完成后 | 分析、复盘 | 某节奏的数据已就绪 |
| `universe.changed` | 平台 | 全体 | 自选池增删 |
| `watch.hit` | 盯盘 | 推送通道、分析（可选） | 单条规则命中，值得看 |
| `watch.digest` | 盯盘 | 推送通道 | 一轮扫描的摘要（即使没有命中也可以发「今日无」） |
| `ask.query` | 用户 / 分析 | 分析 | 一句自然语言或命令 |
| `ask.answer` | 分析 | 用户 | 结构化回答 |

消息必须带：`id`、`ts`、`source_agent`、`idempotency_key`。盯盘同一标的同一规则在冷却期内不得重复推送。

## 5. 平台内核（所有智能体共享，尽量不再长大）

内核保持瘦。能下放到智能体或插件的，就不进内核。

### 5.1 标的 `Instrument`

```
code6        000001
codeFull     000001.SZ
name         平安银行
exchange     SZ
market       hs | bj | kc | fd
```

来源：`hslt/list`（沪深+科创）+ 可选 `bj/list/all`。

### 5.2 股票池 `Universe`

默认 = 现有自选表。操作：加入、移除、分组（自选 / 观察 / 备选）。盯盘默认扫「自选 + 观察」；分析默认展示「自选」。全市场不是默认池，是盯盘的可选扫描插件。

### 5.3 数据内核（唯一允许碰网络）

| 组件 | 职责 | API |
|---|---|---|
| `MarketClient` | 限速、licence、域名、错误归一、真实性门禁 | 全部 |
| `CodeNormalizer` | 按接口族输出 6 位或带后缀 | — |
| `QuoteCache` | 最新行情 | `hsrl/ssjy`、`ssjy_more`、条件允许时 `real/all` |
| `BarStore` | 日线缓存，增量追加 | `hsstock/history` |
| `FundCache` | 财务 / 股东 / 分红 | `hsstock/financial/*`、`hscp/*` |
| `ResultStore` | 按标的聚合后的字段行 | 由 feature 插件写入 |

智能体和插件都只声明「我需要日线 / 行情 / 利润表」，由平台注入。

### 5.4 结果行 `Row`

```
600038.SZ
  quote.price        = 26.86
  bottom.low17       = 24.6      # 不足则 null + reason
  bottom.target      = 36.9
  bottom.gap         = ...
  finance.bps        = 21.43
```

分析智能体拿它填表、回答；盯盘智能体拿它做规则输入。**字段计算只做一次。**

### 5.5 `Notifier`（投递，不是决策）

盯盘决定「推什么」，Notifier 只决定「送到哪」：

| 通道 | 何时用 |
|---|---|
| `log` | 默认，本地文件，必开 |
| `desktop` | 本机通知，可选 |
| `webhook` / 微信 / 邮件 | 以后当通道插件加，现在不绑 |

通道失败不能让盯盘回滚已经算完的结果。

## 6. 插件契约（智能体内部的工具）

插件仍然是「加功能不改内核」的那一层。智能体决定**调用时机**，插件决定**怎么算**。

### 6.1 类型

| 类型 | 干什么 | 主要被谁用 |
|---|---|---|
| `feature` | 给每只标的算一组字段 | 分析（表）、盯盘（规则输入） |
| `scan` | 过滤/排序，产出名单 | 盯盘为主；分析可当 skill |
| `rule` | 读字段 + 上次快照，判断是否「值得推」 | **盯盘专属** |
| `skill` | 问答工具 | **分析专属** |
| `channel` | 把命中送到某处 | 盯盘经 Notifier 调用 |

一个目录可同时声明多种类型：`bottom-value` 既是 feature，也给分析当 skill，也给盯盘当规则输入。

### 6.2 清单示例（feature）

```yaml
id: bottom-value
name: 底部估值
type: [feature, skill]
version: 0.1.0
enabled: true
refresh: eod
requires:
  data: [bars.daily, quote.latest]
  markets: [hs]
provides:
  fields:
    - { key: bottom.low1y,    label: 近1年底,  kind: price }
    - { key: bottom.low17,    label: 17年后底, kind: price }
    - { key: bottom.high,     label: 顶,       kind: price }
    - { key: bottom.off_low,  label: 离底%,    kind: pct }
    - { key: bottom.multiple, label: 高底倍,   kind: ratio }
    - { key: bottom.target,   label: 目标卖价, kind: price }
    - { key: bottom.gap,      label: 比价差%,  kind: pct }
params:
  adjust: n
  long_window_years: 17
  target_uplift: 0.50
  long_window_fallback: shrink
```

### 6.3 规则插件示例（盯盘用，第一版就可以长这样）

```yaml
id: rule-near-bottom
name: 回落到近底部
type: [rule]
owned_by: watcher
enabled: true
requires:
  fields: [quote.price, bottom.low17, bottom.off_low]
params:
  off_low_lte: 0.08          # 离底 ≤ 8%
  min_turnover: 0.01         # 可选：换手过滤
cooldown: 1d                 # 同一标的同一规则冷却
severity: high
reason_template: "{name} 现价 {price}，离17年底 {off_low}%，进入观察区"
```

规则**先写成声明式数据**，不要先写成一段模型自由发挥。第一版「智能」= 准时 + 口径稳定 + 少漏少吵；以后要更聪明，是加规则、加打分器，或再挂一个「研判智能体」来二次筛选，而不是把 Watcher 改成聊天机器人。

### 6.4 失败策略

| 情况 | 行为 |
|---|---|
| 日线不够 17 年 | 字段 `null` + `reason`；依赖它的规则本轮跳过该标的 |
| 市场不支持 | 该插件跳过该行 |
| API 超时 | 平台重试；插件见空缓存，按缺数据处理 |
| 某规则抛错 | 本轮禁用这条规则，其它规则继续 |
| 某智能体抛错 | 运行时隔离，其它智能体继续 |

## 7. 智能体目录

当前只实现两个。第三个及以后只占位，证明槽位是空的。

### 7.1 Analyst · 分析智能体（人对齐）

**职责：** 把数据变成「能看、能问」的东西。不负责主动打扰人。

| 入口 | 行为 |
|---|---|
| 表视图 | 投影 `ResultStore`，复刻并扩展现有 Excel |
| 问答 | 用 skill 查字段、解释口径；没有字段就说没有 |
| 被总线叫醒 | 收到 `watch.hit` 时，可在表上高亮、或在会话里留下一条「盯盘发现」 |

第一批 skill：

| skill | 问法 | 插件 |
|---|---|---|
| `quote` | 现在多少、涨了没 | `quote-basic` |
| `bottom` | 离底多远、目标卖价 | `bottom-value` |
| `xprice` | 某日收在哪 | `x-day-price` |
| `finance` | 净资、研发、收入 | `finance-snapshot` |
| `holders` | 十大流通 | `holder-top10`（P1） |
| `why_hit` | 为什么盯盘推了它 | 读 `watch.hit` 的规则与字段快照 |

分析智能体**不调度行情刷新**（除非用户点「刷新」）。数据由平台或盯盘按日程准备好。

### 7.2 Watcher · 盯盘智能体（钟对齐）

**职责：** 到点取数 → 更新字段 → 用事先写好的规则检测变化 → 把命中推出去。

这是你说的「更智能一点」的第一版，独立于问答。形态会变，但闭环先定死：

```
日程到点
  → 拉/刷新所需数据（行情；日终再拉日线与财务）
  → 跑 feature 插件，得到本轮 Row 快照
  → 与上一轮快照比（价格、离底、是否新进区间……）
  → 逐条启用中的 rule 插件求值
  → 打分 / 去重 / 冷却
  → publish watch.hit（单条）和 watch.digest（本轮摘要）
  → Notifier 投递
```

#### 日程（对齐 API 更新墙钟）

| 任务 | 何时 | 做什么 |
|---|---|---|
| `session-tick` | 交易时段每 N 分钟（先 5 分钟） | 刷新行情；只跑声明了 `realtime` 的规则 |
| `eod-scan` | 每个交易日 20:20 | 追加日线、重算底/顶、跑全部日终规则，出日报 |
| `weekly` | 周六 | 基金持股、概念等慢数据（有插件才跑） |

盘中不算 17 年底部（日线未定）。盘中规则只用「已缓存的底 + 最新现价」。

#### 规则引擎（第一版就要有，但要笨）

输入：本轮 `Row` + 上轮快照 + 规则参数。  
输出：`WatchHit`：

```
code, name
rule_id, severity
reason                 # 人能读的一句
fields_snapshot        # 命中时的关键字段，供分析和复盘
score                  # 0~1，先用规则静态权重，以后可换模型
```

第一批规则（均可关，均可改参数）：

| 规则 | 触发大意 | 依赖字段 |
|---|---|---|
| `near-bottom` | 离 17 年底（或实际窗口底）≤ N% | `bottom.off_low` |
| `near-target` | 距目标卖价不足 N%，考虑减 | `bottom.gap` |
| `break-xday` | 现价相对「X 日价」变化超过 N% | `quote.price` + `xday.price` |
| `limit-up-in-pool` | 自选里出现涨停（接股池接口后） | `hslt/ztgc` |

「有价值」在第一版 = **规则命中且过冷却**。不在第一版做：模型选股、盘感总结、自动调参。这些留给以后的研判智能体或 Watcher 的打分插件。

#### 降噪（比多推更重要）

- 同一 `(code, rule_id)` 冷却（默认 1 个交易日）。
- 一轮最多推 K 条（默认 10），按 `score` 截断，其余进 digest。
- 字段为 `null` 的规则不命中，不发「数据缺失当利空」。
- 非交易日 `session-tick` 直接跳过。

### 7.3 预留智能体（只占位）

| id | 将来可能干什么 | 现在做什么 |
|---|---|---|
| `reviewer` | 收盘后对照命中与次日走势，给规则打分 | 空清单 `enabled: false` |
| `researcher` | 业绩预告、股东变动、解禁的叙事摘要 | 同上 |
| `flow-watcher` | 资金流异常（依赖 `transaction` 接口） | 同上 |

占位的意义：运行时按目录扫描智能体，空的也不会报错；命名冲突现在就能避开。

## 8. 能力插件分级

插件是系统的工具箱，**不属于某一个智能体私有**（`rule` / `skill` / `channel` 除外，它们有主）。

### 8.1 P0 · 两个智能体都能转起来

| 插件 | 类型 | 分析侧 | 盯盘侧 | 数据 |
|---|---|---|---|---|
| `quote-basic` | feature | 表现价列 | 盘中规则输入 | `hsrl/ssjy` / `ssjy_more` |
| `bottom-value` | feature + skill | 表 + 问答 | 近底/近目标规则 | 本地日线 `min(l)` / `max(h)` |
| `x-day-price` | feature + skill | X 日价列 | `break-xday` | 日线按日取 `c` |
| `finance-snapshot` | feature | 净资/收入/研发/其他收益 | 暂不进第一批规则 | `pershareindex` + `income`（`btsr`→`qtsy`） |
| `dividend-history` | feature | 每10股派息 | 暂不用 | `hscp/jnfh` |
| `rule-near-bottom` | rule | — | 推「接近底部」 | 读 `bottom.*` |
| `rule-near-target` | rule | — | 推「接近目标卖价」 | 读 `bottom.*` |
| `channel-log` | channel | — | 命中落盘 | — |

`bottom-value` 口径：复权默认 `n`；17 年不够则 `shrink` 并标明实际窗口。公式全是参数。

P0 完成标准：

- 表能对上现表已识别列。
- 分析能回答现价 / 离底 / 目标 / X 日价。
- 盯盘能在 20:20 自动跑一轮，把命中写进日志（即使你还没看表）。

### 8.2 P1 · 插进系统，不改两个智能体的外壳

| 插件 | 谁受益 | API |
|---|---|---|
| `holder-top10` / `capital-structure` / `holder-change` | 分析列 + 以后的研判 | `financial/topholder` `flowholder` `hm` `gdbh` |
| `earnings-preview` / `unlock-schedule` | 分析 + 可升为规则 | `yjyg` `jjxs` |
| `limit-pool` | 盯盘扫描自选是否在涨停池 | `hslt/ztgc` 等 |
| `why_hit` skill | 分析解释盯盘为什么推 | 读 `watch.hit` |

### 8.3 P2 · 只登记

资金流、MACD/KDJ、概念、基金持仓、逐笔、北交所、webhook 通道。需要时复制 `_template`。

## 9. 主数据流

### 9.1 交易日盘中（盯盘主导）

```
Watcher.session-tick
  → QuoteCache 刷新池内行情
  → 仅 realtime feature / rule
  → 命中则 watch.hit + 冷却
  → Notifier
Analyst 不参与，除非用户打开表或发问（读缓存）
```

### 9.2 交易日 20:20（日终）

```
Watcher.eod-scan
  → 增量日线、财务
  → 全量 feature（底/顶在这里重算）
  → 全量日终规则
  → watch.digest（今日命中列表 + 无命中也报一声）
  → publish data.ready
Analyst 之后打开表即是当日收盘口径
```

### 9.3 人问一句

```
用户 → ask.query → Analyst
  → 需要的字段若已在 ResultStore，直接答
  → 缺 on_demand 数据（如指定 X 日）再请平台补
  → 不问 Watcher，除非用户问「今天推了谁 / 为什么推」
```

## 11. 落地顺序

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| **S0** | 正式 licence 跑验证脚本 | 日线真实深度清楚；Watcher 的 17 年规则能定窗口或 `shrink` |
| **S1** | 平台：Instrument、Universe、MarketClient、缓存、总线、插件注册 | 40 只池可增量缓存；演示 licence 写不进库 |
| **S2** | P0 feature + 只读表（此时可以还没有「智能体」外壳，先当平台服务） | 与现表列对齐 |
| **S3** | **Watcher 独立进程**：日程 + 两条规则 + `channel-log` | 不打开表，到点也能在日志里看到命中/空报 |
| **S4** | **Analyst 独立进程**：问答 skill + 可读 Watcher 的 hit | 能问现价/离底；能问「今天推了谁」 |
| **S5** | 插一只新插件（股东或涨停池）**且不改两个智能体外壳** | 架构验收 |
| **S6** | 需要时再挂第三个智能体（建议 `reviewer`） | 只加 `agents/reviewer`，总线能订阅 `watch.hit` |

S3 提前于完整问答，是有意的：先证明「定时 → 取数 → 规则 → 推送」这条闭环不必依附聊天。S4 才把分析智能体补齐。S6 证明「加智能体」和「加插件」一样廉价。

## 13. 成功标准（判断设计有没有走歪）

1. **加能力不改平台。** 新列 / 新规则 / 新通道 = 新插件目录。
2. **加角色不改旧智能体。** 第三个智能体 = `agents/` 下新目录 + 订阅已有主题。
3. **两个智能体可单独活。** 只起 Watcher 能推送；只起 Analyst 能查表问答。
4. **现表可复刻。** P0 字段能从 `ResultStore` 投影出来。
5. **盯盘闭环不依赖聊天。** 无人值守也能按规则出 hit / digest。
6. **口径可改、数据不足不崩。** 规则在字段为空时沉默，不胡推。
7. **智能体不编造。** 分析没有字段就说没有；盯盘没有命中就说本轮无，不补故事。

若出现下面任一情况，视为回退：公式写进平台；插件自己发 HTTP；用一个大 prompt 同时负责问答和扫描；为了推送方便把 Watcher 写进 Analyst 内部。
