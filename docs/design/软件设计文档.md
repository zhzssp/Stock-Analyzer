---

## 0. 一句话

软件有两条并行的产品线，共用同一套数据与扩展机制：

1. **传统查询**：用户选定股票池和字段 → 调数据源 → 表格展示 → 导出 Excel。确定性、可复现、不依赖大模型。
2. **Agent 系统**：内置可增删的自定义智能体。麦蕊 API、传统查询留下的历史 Excel、以及以后新接的数据源，一律注册成 **Tool**。用来做灵活问答、定时监控、趋势分析，分析结果同样能导出 Excel。

加功能的主路径永远是：**加 Tool / 加字段插件 / 加智能体**，而不是改核心循环。

## 1. 产品定位

### 1.1 给谁用

小范围使用者（个人或小团队）在 **PC 上登录**后使用。主要盯自选股，顺带按条件从沪深、北交所等市场筛数。不面向公网海量用户，不接交易下单。

### 1.2 用户每天怎么用

| 场景 | 走哪条线 |
|---|---|
| 打开自选表，扫现价、行业、股东、财务 | 传统查询 |
| 把当前结果存成 Excel，以后对照 | 传统查询导出；同时成为 Agent 可读的历史档案 |
| 「这只为什么跌、和铜价有没有关系」 | Agent 问答（调行情 / 期货 / 历史表 / 新闻 Tool） |
| 十大流通股东变了、政策动了、连跌三天的期货和自选相关 | Agent 定时监控，推送到本机 |
| 把今晚的监控结论再导出一张表 | Agent 导出 |

### 1.3 明确不做

- 自动下单、荐股承诺、收益保证。
- 公网多租户、高并发、微服务拆分。
- 第一期不做全市场每秒级扫描。
- 没有数据时不让模型编造数字。

## 2. 对客功能（结合两张需求图）

### 2.1 功能一：传统查询 + 表格 + 导出

**形态：** PC 登录后进入查询工作台。左侧股票池三个入口：自选（可增删改、可从沪/深/科创/北交所筛选导入）、行情（指数成份）、交易所（沪市全部 / 深市全部 / 北交所全部，分开导出）。中间是结果表，右上是「查询 / 刷新 / 导出 Excel」，并标明当前导出哪一个池。

**图 1 希望包含的结果字段（第一期查询列清单）：**

| 列 | 含义 | 主要数据来源（麦蕊） | 备注 |
|---|---|---|---|
| 名称 | 证券简称 | `hslt/list` `mc` | |
| 代码 | 带市场后缀 | `hslt/list` `dm`（实测已是 `000001.SZ`） | |
| 最新价 | 现价 | `hsrl/ssjy` `p` | |
| 涨跌幅 | 当日涨跌% | `hsrl/ssjy` `pc` | |
| 所属行业 | 申万等行业 | `hszg/zg` | 备注里的申万 2025 版 31/134/346 三级，接口树需对照后映射 |
| 所属概念/板块 | 概念、板块 | `hszg/zg`、`hscp/gsjj.idea` | 多值，表内可折叠 |
| 主营业务 / 经营范围 | 公司做什么 | `hscp/gsjj` `bscope` / `desc` | |
| 前十大流通股东 | 名单摘要 | `hsstock/financial/flowholder` | 单元格展示前 N 名 + 可点开明细 |
| 总股本 | | `financial/capital` `zgb` 或 `instrument.tv` | |
| 流通股本 | | `capital.ysltag` 或 `instrument.fv` | |
| 每股未分配利润 | | `pershareindex.mgwfplr` | |
| 研发费用 | | 利润表 `yffy` | |
| 每股净资产 | | `pershareindex.mgjzc` | |
| 每股收益 | | `jbmgsy` | |
| 市盈率 | 动态 PE | `hsrl/ssjy` `pe` | |
| 毛利率 | | `pershareindex.xsmlv` | |
| 净利率 | | `pershareindex.jlv` | |

列是**插件化**的：以后要加「底/顶/目标卖价」「换手」「市净率」等，只加字段插件并在列清单里打开，不必改表组件。

**导出：** 当前结果一键导出 `.xlsx`，带查询时间、股票池名称、字段口径。文件落入本地档案库，并登记一条「导出记录」，供 Agent 当 Tool 读取。

**筛选导入（图 2-①）：** 除自选外，可对沪深、北交所列表做条件筛选（行业、代码前缀等），勾选后并入自选或一次性查询。北交所财务/股东列允许为空。

### 2.2 功能二：Agent 问答与监控

用户侧看到的是「对话 + 监控任务 + 分析导出」，不是框架名词。

| 能力 | 用户感知 |
|---|---|
| 知识问答 | 输入公司名/代码/自然语言，Agent 调 Tool 取数后回答，并给出引用（哪张表、哪个接口、哪份历史 Excel） |
| 定时监控 | 用户打开若干监控项（或使用预置规则），到点跑分析；命中则提醒 |
| 趋势分析 | 定时或手动：「当前和自选相关的市场在发生什么」——综合行情、板块、资金、（有 Tool 时）期货与新闻 |
| 分析导出 | 一轮问答或一轮监控的结论导出 Excel |

### 2.3 图 2 定制需求如何落到两条产品线

| # | 需求（归纳） | 传统查询 | Agent / 监控 | 数据是否已有 |
|---|---|---|---|---|
| ① | PC 登录；自选增删；沪深/北交所筛选；导出 Excel | **主功能** | 导出档案成为 Tool | 列表、行情已有；北交所仅行情 |
| ② | 十大股东增减、定增/激励/合资/并购/回购/分红/减持等重大变化，自动提醒 | 表上可看股东、分红、增发、解禁 | **Watcher 规则 + 事件 Tool** | 股东/分红/增发/解禁有；激励、并购、减持需公告/新闻类 Tool（后续加） |
| ③ | 自选相关行业/概念的国家产业政策、产业基金、主动基金调仓，自动提醒 | 行业/概念列 | **政策/基金监控 Agent** | 概念树、基金持股有一部分；政策新闻需检索 Tool |
| ④ | 按公司/行业查相关期货；有色/矿业看工业品、农产品近一周；品种连涨连跌 3 日且与自选相关则提醒 | 可做「关联品种」只读列（后期） | **期货 Tool + 监控规则** | `hszg` 含期货分类；完整外盘行情（WTI、布伦特等）当前麦蕊覆盖不明，按独立数据源 Tool 预留 |
| ⑤ | 按名称搜微博/财经站点快讯与链接；可能影响自选价格则提醒 | — | **资讯检索 Tool + 监控** | 麦蕊无此接口，必须新增 Tool |
| ⑥ | 自选每日资金流入/流出、净流入、北向资金 | 可做成查询列 | 监控可盯异常流入 | 个股资金流有 `history/transaction`；北向需确认或另接 |
| ⑦ | 公司产品出口及外市场占比 | 有数据则加列 | 问答可引用 | **当前 API 无**，先做研究型 Tool（网页/人工录入），不阻塞其它功能 |

**原则：** ①⑥ 和表内字段先做实；② 中已有接口的事件先做；④⑤⑦ 和 ② 的缺口按 Tool 插槽实现，接口未就绪时监控项显示「未启用」，不假装有数。

图 2 备注中的**申万行业三级分类（2025）**、**国际期货品种树**（能源 / 化工 / 金属 / 农产品 / 金融）作为平台里的「分类主数据」插件，供查询筛选和 Agent 关联，而不是写死在某个页面里。

## 3. 总体架构

```
┌──────────────────────────── PC 客户端 ────────────────────────────┐
│  Vue 工作台：登录 · 自选 · 传统查询表 · 导出 · Agent 对话 · 监控中心 │
└─────────────────────────────┬────────────────────────────────────┘
                              │ HTTP / JSON（本机）
┌─────────────────────────────▼────────────────────────────────────┐
│  应用服务  FastAPI                                                │
│  · 认证  · 查询编排  · 导出档案  · Agent 网关  · 任务调度入口       │
└───────┬───────────────────────────┬──────────────────────────────┘
        │                           │
        ▼                           ▼
┌───────────────┐          ┌───────────────────────────────────────┐
│ 查询引擎       │          │ Agent 管控运行时（自研外壳）            │
│ QueryEngine    │          │ · 问答：iter_agent 多轮 Tool 循环       │
│ 字段插件编排   │          │ · 调度：watcher / reviewer 作业        │
│                │          │ · Tool 注册表（唯一对外能力入口）      │
└───────┬───────┘          └──────────────────┬────────────────────┘
        │                                     │
        └──────────────────┬──────────────────┘
                           ▼
        ┌──────────────────────────────────────┐
        │ 平台内核（两条线共用）                 │
        │ MarketClient / CodeNormalizer         │
        │ BarStore · QuoteCache · FundCache     │
        │ Universe · ArtifactStore(Excel档案)   │
        │ Taxonomy（行业/概念/期货品种）         │
        │ Notifier · Scheduler                  │
        └──────────────────┬───────────────────┘
                           ▼
              麦蕊 API  +  后续其它数据源适配器
```

两条线**禁止**各自发 HTTP。查询引擎和 Agent 都只能通过平台内核和 Tool 注册表拿数。这样换 licence、加第二个行情源、改 Excel 目录，两边一起生效。

扩展的三条轴（必须始终保持）：

```
加一列查询字段     →  字段插件
加一种取数/动作    →  Tool（API / Excel / 新闻 / 期货 / ……）
加一种自主行为     →  智能体（问答、盯盘、复盘、研报……）
```

## 4. 技术选型

用户少、部署在 PC、以后要不断加 Tool——选型优先 **一个人能维护、Python 生态对 Agent/表格友好、本地能跑完**。

### 4.1 一览

| 层 | 选型 | 为什么 |
|---|---|---|
| 前端 | **Vue 3 + TypeScript + Vite + Element Plus + Pinia** | 金融表、筛选、抽屉明细、中文组件成熟；比 React 更适合这种「后台表格式」工作台 |
| 桌面壳 | **第一期：本机浏览器打开服务**；第二期用 **Electron** 包成安装包（登录窗 + 内嵌前端） | 第一期少一层构建；「装在 PC、登录使用」第二期用 Electron 对齐图 2-①，不必上 C/S 重客户端 |
| 后端 | **Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2** | 与 Agent、pandas、现有验证脚本同一语言；FastAPI 适合本机 API 和以后给 Agent 当 HTTP Tool |
| 库 | **SQLite**（SQLAlchemy 操作） | 单机足够；用户量上来再迁 PostgreSQL，DAO 已隔离 |
| 表格/导出 | **pandas + openpyxl** | 查询结果、Agent 分析报告都走同一套导出 |
| Agent 运行时 | **自研外壳 + 直线 Tool 循环**；LangGraph 仅作将来可选内层 | 本机要的是会话、白名单、调度、cite；图库不回答这些。细则只认 [智能体运行时](./智能体运行时.md) |
| 定时 | **APScheduler**（进程内） | 小用户不必上 Celery/Redis；与 FastAPI 同进程即可 |
| LLM | **DeepSeek**（OpenAI 兼容 Chat Completions + Tool Calling） | 默认 `https://api.deepseek.com/v1`、`deepseek-chat`。编排与写答案都走兼容接口；不绑 SDK。`deepseek-reasoner` 不做 Tool 选择 |
| 认证 | 本地用户表 + **Session Cookie / JWT** | 小团队几个人登录足够；密码哈希用 passlib |
| 测试/探针 | `Verify-Api.ps1` + `Verify-Index.ps1`，后端再用 pytest | 数据源门禁不丢；指数成份未证实不启用 |

### 4.2 不选什么（避免过度设计）

| 不选 | 原因 |
|---|---|
| Spring / Java 单体 | Agent、pandas、Excel 分析在 Python 更顺；当前仓库与验证脚本也是这个方向 |
| 微服务 + 消息队列 | 用户少，运维成本高于收益 |
| 仅 Streamlit / Gradio | 传统查询表 + 权限 + 导出档案会很快顶到天花板 |
| 把问答和扫描写成一个超级 Agent | 已在多智能体专论里否决；角色显式拆开，不是一个图里靠 prompt 路由 |
| 把 LangGraph 当生产外壳 | 库不是会话/权限/工具网关；本机用 Mode A：外壳自研，内层默认同构循环 |
| 第一期就上 Kubernetes / 云数据库 | 与「PC 安装」不符 |

### 4.3 Agent 框架怎么用（避免选了框架却焊死）

细则只认 [智能体运行时](./智能体运行时.md)。这里只留四条硬约束：

- 每个智能体 = **一种触发方式**（聊天 / cron）+ **一份 YAML 白名单或规则清单**。不是「一张 LangGraph 图」。
- Tool 不写进编排硬编码里，从 `config/agents/*.yaml` 或规则模板注入。
- 新增 Tool：实现统一接口、登记 YAML；无源则 `enabled: false`，工作台不假装有数。
- 监控与复盘默认**结构化规则 / 状态机**；LLM 只做可读摘要，可关。watcher / reviewer 不进对话图。

### 4.4 前端与后端的职责切分

| 前端 | 后端 |
|---|---|
| 登录、自选维护、列显隐、表格虚拟滚动 | 鉴权、查询编排、字段计算、缓存、限速 |
| 对话 UI、监控开关、通知列表、复盘子页 | Agent 循环执行、Tool 调用、任务调度、复盘打标 |
| 点「导出」下载文件 | 生成 xlsx、写入 ArtifactStore |
| 不直接调麦蕊 | 不写死某一列表头（列来自字段注册表） |

## 5. 传统查询子系统

### 5.1 流程

```
选当前池（自选 / 交易所全市场 / 已启用的指数成份 / 粘贴代码）
  → 选列（默认图 1 清单，可勾选）
  → POST /api/query/run
  → QueryEngine 按列依赖拉数、拼 Row
  → 前端表格
  → POST /api/query/export  →  xlsx + 档案记录
```

查询是**同步或短异步**（40 只池秒级；若筛选出几百只则返回 `job_id` 轮询）。不做分布式任务队列。

**当前池口径（S5/S6）：** 侧栏或顶栏选中哪个池，查询和「导出 Excel」就导哪个池，表头仍是图 1。两条名单不得混名：

| 入口 | 名单 | 禁止写成 |
|---|---|---|
| 自选 | 用户自选 | — |
| `exchange:sh` / `sz` / `bj` | 该交易所全部挂牌 | 上证指数 / 深证成指 / 北证50 |
| `board:cy` / `board:kc` | 创业板全部 / 科创板全部（代码前缀） | 创业板指 / 科创综指 |
| `index:{code}` | 该指数成份股（离线用切片；正式 licence 以 S0 探针为准） | 用交易所全部冒充成份 |

演示 licence 忽略股票代码，全市场导出必须拒绝，不得把样本写成实盘。离线模式只给切片并标明「非全市场实盘」。

### 5.2 字段插件契约

```yaml
id: pe_ttm
label: 市盈率
group: quote
enabled: true
requires: [quote.latest]
provide: { key: quote.pe, type: number }
```

```
compute(instruments, ctx) -> { code: value }
```

QueryEngine 按 `requires` 拓扑排序。Agent 读到的 `Row` 与表是同一套 key，问答和监控不用再算一遍。

### 5.3 导出档案（给 Agent 用的历史 Excel）

每次导出写入：

```
data/artifacts/query/{yyyyMMdd-HHmmss}_{pool}_{id}.xlsx
```

元数据入库：`artifact_id`、时间、股票列表、列清单、文件路径、备注。

每人默认只留最近 20 份（`ARTIFACT_KEEP`）。超出的文件和库记录一起删，避免档案库幽灵路径。可在工作台「本机数据」立刻「只留最近导出」。

对 Agent 暴露的 Tool 例如：

- `excel_list`：列出近期导出
- `excel_read`：按 id 读成表格（可限制行数）
- `excel_diff`：两份导出按代码对齐，比某列变化（股东、现价等）

这样「上周导过的表」天然成为知识，而不必再打一次 API。

### 5.4 本机 `data/` 占用

默认目录仍是软件根下的 `data/`（可用 `DATA_DIR` 覆盖，不作为默认）。不进 git。

| 路径 | 性质 | 控制 |
|---|---|---|
| `data/app.db` | 用户资产 | 不自动删；备份整夹 |
| `data/artifacts/query/*.xlsx` | 用户导出 | 每人最多 `ARTIFACT_KEEP`（默认 20） |
| `data/cache/*.json` | 可再拉的缓存 | 同一 key 覆盖写；总上限 `CACHE_MAX_MB`（默认 300）；超限按 LRU 先删日线，名单缓存尽量留到最后 |
| `data/alerts.log` | 追加日志 | 超过 `ALERTS_LOG_MAX_MB`（默认 2）裁切尾部 |

日线缓存键为 `bars_{code6}_{复权}`，只在有人查过该票时写入，滚动最多 `BARS_MAX`（默认 500）根，不预拉全 A。启动（非 pytest）和交易日 20:20 收盘任务会再扫一遍上限。工作台 `GET /api/storage`、清缓存、裁导出。

四人在不租服务器的前提下留下盘中横切面、按墙钟做时段分析：不把整份 `data/` 做网盘同步。设计见 [墙钟行情账本](./墙钟行情账本.md)（用户选一个网盘共享文件夹、一档一文件、软件自动读写；麦蕊次数充裕，重复查询可接受）。**未落地前现价仍各机直连麦蕊**；落地后 `MarketClient` 仍是唯一对麦蕊发 HTTP 的模块，共享档够用则用，否则本机拉并尽量写档。

## 6. Agent 子系统

### 6.1 四个预置智能体（可关、可再加）

| id | 触发 | 作用 | 第一期白名单 / 规则 |
|---|---|---|---|
| `analyst` | 用户发问 | 问答、解释口径、引用表/Excel | YAML：`excel_parse` `warehouse_get` `market_fetch` `quote` 等 |
| `researcher` | 「看市场」或路由词 | 综合自选盘面；注入队列、命中、复盘摘要 | YAML 白名单；未就绪 Tool 跳过 |
| `watcher` | 日程 / 手动「跑一轮」 | 规则检测，推送 | 模板 + 自定义规则；不进对话图 |
| `reviewer` | 20:20 在 watcher 之后 / 立刻复盘 | 命中的次日打标 | `config/agents/reviewer.yaml`；调度作业，前端在监控「复盘」 |

加第五个角色：聊天走同一 `iter_agent` + YAML；作业走调度 + 业务表。不要默认加一张 LangGraph 图。细则：[智能体运行时](./智能体运行时.md)。

### 6.2 Tool 契约（最重要的扩展点）

```yaml
id: capital_flow
name: 个股资金流
version: 0.1.0
enabled: true
kind: market          # market | artifact | web | compute
auth: none
input_schema:         # JSON Schema，供 LLM function calling
  code: string
  days: integer
output_schema:
  net_in: number
  ...
impl: tools.capital_flow:run
```

统一运行接口：

```
run(args, ctx) -> ToolResult(ok, data, source, as_of, error)
```

`ctx` 只给：规范化标的、缓存、用户、限额。Tool **不得**自己读 licence 文件、不得自己写 Excel（写档案走 `ArtifactStore`）。

**第一期就要有的 Tool：**

| Tool | 给谁 | 背后 |
|---|---|---|
| `universe` | 两边 | 自选增删查 |
| `quote` | 两边 | 行情缓存 |
| `company_profile` | 查询列 + 问答 | `gsjj` + 行业概念 |
| `holders_flow` | 查询列 + 监控② | `flowholder` |
| `finance_snapshot` | 查询列 + 问答 | 每股指标 + 利润表 |
| `capital` | 查询列 | 股本 |
| `query_run` | Agent 需要「现查一张表」时 | 内部调用 QueryEngine |
| `excel_parse` | 对话里粘贴/上传的 Excel、CSV、TSV、HTML 表 | 解析后写入档案库 |
| `warehouse_get` | 仓库历史：导出档案、缓存、日线 | ArtifactStore + `data/cache` + `MarketClient.history` |
| `market_fetch` | 按 `resource` + 代码直接查实盘/离线切片 | `quote/profile/holders/finance/history/capital_flow/events` |
| `excel_list` / `excel_read` / `excel_diff` | Agent | ArtifactStore |
| `watch_card` | 两边 | 自选决策卡 |
| `watch_rules` | 两边 | 用户在监控中心保存的规则定义 / 监控需求 |
| `watch_review` | 两边 | 次日复盘标签 |
| `capital_flow` | 查询列⑥ + 监控 | `history/transaction` |

**预留、接口或数据源就绪再打开：**

| Tool | 对应需求 |
|---|---|
| `corp_events` | ② 激励/并购/减持等（公告源） |
| `policy_news` | ③ 产业政策 |
| `fund_holding` | ③ 主动基金（`jjcg` 可先做弱版） |
| `futures_quote` | ④ 关联期货与连涨连跌 3 日 |
| `web_finance_search` | ⑤ 微博/财经站点 |
| `export_share` | ⑦ 出口占比（网页或手工表） |

未实现的 Tool 在注册表里 `enabled: false`，监控任务若依赖它，界面显示「缺少数据源」，不会空跑后胡说。

### 6.3 监控任务（图 2 的「自动预警」）

用户（或预置）创建任务：

```yaml
id: holders-change
agent: watcher
schedule: "0 21 * * 1-5"    # 日终后
tools: [holders_flow, excel_diff]
rule:
  type: holders_delta       # 自动扫描仍是结构化规则，不是自由 prompt
  params: { min_change_pct: 0.5 }
notify: [log, desktop]
```

用户可另存 **规则定义 / 监控需求** 两段文字（默认在界面收起）。这两段只注入 analyst / researcher 的上下文，**不**改 watcher 的判定函数。无指标的自定义规则只给问答用。

第一期预置任务与图 2 对齐：

| 任务 | 规则大意 | 依赖 |
|---|---|---|
| 股东变动 | 十大流通名单或持股较上次导出/上次快照变化 | ② |
| 公司事件 | 分红、增发、解禁（已有）；其它事件等 Tool | ② |
| 产业/基金 | 有新闻或基金持仓 Tool 后再开 | ③ |
| 期货联动 | 关联品种 3 日同向且自选在该行业 | ④ |
| 资讯冲击 | 检索命中且模型/关键词判定相关 | ⑤ |
| 资金异常 | 净流入偏离近 N 日 | ⑥ |

降噪：同一 `(code, rule)` 冷却 1 个交易日；每轮最多推 K 条；缺数据不推。

### 6.4 推送

第一期：本机通知列表 + 日志文件。Electron 阶段再加系统托盘气泡。Webhook / 微信当 **Channel 插件**，与决策分离。

|---|---|---|
| POST | `/auth/login` | 登录 |

## 10. 数据源缺口与对策

实现前必须承认：图 2 不是麦蕊一张网能盖完的。架构上用 **adapter + Tool** 挡着，避免页面写死「一定有期货、一定有微博」。

| 需求 | 现状 | 对策 |
|---|---|---|
| 图 1 大部分列 | 麦蕊可拼出 | 第一期做实 |
| 沪深+北交所列表 | 两套 list | Universe 合并；北交所列财务为空；S5 按交易所切全市场 |
| 指数成份股 | 仅有个股反查 `hscp/sszs`，无已证「指数→成份」 | 离线用切片启用行情芯片；正式完整名单等 S0 探针；禁止用全市场冒充 |
| 股东/分红/增发/解禁 | 有 | 先做 ② 的这一半 |
| 激励/并购/减持 | 无专用字段 | `corp_events` Tool 插槽 |
| 产业政策、微博财经 | 无 | `web_finance_search` / `policy_news` |
| 外盘期货完整行情 | 分类树可能有，行情深度未知 | `futures` adapter，可接第二个 API |
| 北向资金 | 需核实 | 有则列⑥，无则标明未接入 |
| 出口占比 | 无 | 手工表或研究 Tool |

平台已要求：演示 licence 不得写入缓存（沿用验证脚本的真实性门禁）。

## 11. 安全与运行（小用户也要有的底线）

- 本机默认绑定 `127.0.0.1`，不对外网开放。不要为共享现价把整站绑到公网；墙钟胶带用网盘共享文件夹，见 [墙钟行情账本](./墙钟行情账本.md)。
- 登录后才能查数、才能跑 Agent。
- Tool 出站（麦蕊、以后的搜索）走白名单域名。
- Agent 导出的 Excel 与传统导出同一目录权限。
- 提示用户：监控结论不是买卖指令。

## 12. 分期落地

每期结束都要能单独使用，并且验证「加东西不改核心」。

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| **S0** | 正式 licence 跑通 `Verify-Api.ps1` **与** `Verify-Index.ps1` | 日线深度、代码格式；有没有「指数→成份」，没有则只证伪、不启用指数芯片 |
| **S1** | FastAPI + SQLite + 登录 + Universe + MarketClient | 本机登录后能看到自选（可先手工导入 40 只） |
| **S2** | QueryEngine + 图 1 全部列 + 表格 + 导出 Excel | 与需求表对齐；档案入库 |
| **S3** | 沪深/北交所筛选进自选 | 图 2-① 闭环（离线已落地） |
| **S4** | 自研 `analyst` 多轮 Tool 循环（不是 LangGraph 图）+ 第一批 market/excel Tool | 能问现价、股东、财务，并能引用刚导出的 Excel（离线已落地） |
| **S5** | 行情工作台 + 交易所全市场 | 自选 / 行情 / 交易所 三个入口；`exchange:*` / `board:*` 在「交易所」按图 1 查表导出（大池走任务）；不得把这些芯片放进「行情」、不得贴指数名 |
| **S6** | 指数成份行情 | 工作台「行情」只列指数芯片；离线用成份切片启用上证指数 / 深证成指 / 北证50 等；点芯片列出成份并查/导。正式 licence 完整成份仍只在 S0 探针命中后替换切片；未证实不得用全市场冒充 |
| **S7** | `watcher` + 股东变动/资金流/事件/接近底部 + 本机提醒列表 | 不打开对话也能出 hit（离线已落地；期货/资讯仍未启用） |
| **S8** | 加**一个**新 Tool（建议资讯检索或期货）且不改 QueryEngine / 图结构 | **扩展验收**。必做三件已落地；资讯/期货/政策以 YAML 插槽 `enabled: false` 登记，不假装有数 |
| **S8.1** | 本机消息总线 + Channel（log / desktop / webhook） | watcher 发 `watch.hit` / `watch.digest`；自选变更发 `universe.changed` |
| **S8.2** | `agent_sessions` 多轮对话 | `/agent/chat` 带 `session_id`，下一问能接上轮股票 |
| **S8.3** | 真流式 SSE | Tool 边跑边推；有 DeepSeek key 时答案按 token 推 |
| **S8.4** | `researcher` | 「看市场」综合自选行情/板块/资金；未就绪 Tool 跳过 |
| **S8.5** | `reviewer` 跨日复盘作业 | 命中写入命中价；20:20 后按下一根交易日收盘打标。调度作业，不是 LangGraph 图；不自动关规则 |
| **S9** | Electron 壳 + 托盘气泡 | Channel 已预留 webhook；安装包仍后置 |

S8 不过，不允许继续堆 ③④⑤⑦ 的页面假数据。S5 芯片不得把深市全部写成深证成指、把北交所全部写成北证50。

## 13. 成功标准

1. 传统查询不依赖 LLM，断网模型 key 失效时表还能刷缓存/还能打开历史 Excel。
2. Agent 断了查询引擎也不该瘫痪：它走 Tool，查询只是 Tool 之一。
3. 加一列 = 加字段插件；加一种取数 = 加 Tool；加一种自主行为 = 加智能体（聊天循环或调度作业），不是默认加一张 LangGraph 图。
4. 图 1 列在 S2 齐；交易所全市场 API 在 S5 齐；指数成份在 S6 齐（2026-09-21：正式证探针已证实上证指数 / 深证成指 / 北证50 / 创业板指 / 中证500 / 上证50 六个指数的官方成份并替换切片；未证实的指数仍不得用全市场冒充）；图 2 已有数据源的监控在 S7 齐。
5. 导出的 Excel 既能给人看，也能被 Agent 当历史知识读。
6. 不出现：页面写死麦蕊 URL、Agent 自己拼股票代码、用一段 prompt 同时负责查表和扫描。
