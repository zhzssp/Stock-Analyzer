## 0. 一句话

不租云主机、不把整站做成公网服务。四人本机各跑助手，都是取数员。盘中按上海墙钟切档（先 5 分钟）：共享文件夹里**有**这一档、且自己要用的代码都在，就直接用；没有或缺代码，就本机打麦蕊，再尽量把结果写进这一档。重复查询、两台同时写、网盘慢几秒，都可以接受。用户只选一次网盘共享目录，软件自己读写，不对客出现 GitHub / 提交 / Push。盯盘和表格能用本机刚拉到的价，不必干等网盘；事后分析只认文件夹里带 `as_of` 的档。

## 1. 背景与约束

### 1.1 产品形态（不变）

- 助手是本机进程：FastAPI 默认绑 `127.0.0.1`，SQLite + `data/` 在软件根下。
- 大约四个人使用。每人一台电脑，只跑自己的任务。
- **不租服务器、不把控制面统一部署到一台云主机。** 这是本方案存在的原因，不是因为额度不够。
- 也不另买 NAS / 常开「行情网关」电脑。网盘共享文件夹不是服务器，只是四人本来就会用的同步盘。
- 四人按「不会用 GitHub、不会命令行」来设计对客路径。
- 不下单、不荐股。无源不编数字。演示 licence 不得当成实盘写入任何账本。

### 1.2 额度前提（本版起升格为硬前提）

麦蕊套餐允许的查询次数相对四人小池子、盘中按分钟级刷新，是充裕的。因此：

- **不要**为省几次 HTTP 引入锁、抖动等待、丢弃已经打成功的结果、或在网盘延迟时冻结界面。
- 同一档被两台各打一遍，可以。启动探测多打三枪，可以。某人网盘还没同步到、自己先拉了一次，可以。
- 仍避免无意义的死循环和全市场误扫（并集硬顶还在），那是防误操作，不是省套餐。

本方案要解决的是：**没有统一后端时，盘中横切面如何留下来、四人如何大致对着同一条墙钟说话。** 不是「全网只许一次 `ssjy_more`」。

### 1.3 钥匙怎么分

| 秘密 | 谁持有 | 进不进共享账本文件夹 |
|---|---|---|
| 麦蕊 `MAIRUI_LICENCE` | 一份套餐，四台 `.env` 都可以有（谁要打麦蕊谁就得有） | **禁止** |
| 大模型 `LLM_API_KEY` | 各人自充、只写在自己电脑的 `.env` | **禁止** |
| `app.db`、决策卡成本、对话 | 各人本机 | **禁止** |
| 档口现价 JSON、各人想看的代码表 | 共享账本文件夹 | 要进（这就是档案） |

模型调用永远走各机 `llm.py`，不经过网盘，也不经过任何租来的后端。

### 1.4 现有代码里的缺口

| 现状 | 后果 |
|---|---|
| `MarketClient.quote` / `quotes_many` 每次直连且不落共享档 | 四人各有各的「现在」，事后无法回放「10:05 我们看见什么」 |
| `list_hs`、日线已有本机 `data/cache` | 名单和日线不必进墙钟文件夹 |
| 盘中调度约每 5 分钟；用户希望更密 | 没有档案时，历史分钟横切面不可再造（麦蕊不会把上周二 10:05 的并集再卖给你） |
| 启动方式是黑窗口 | 关窗口则没人往文件夹里补档；与额度无关 |
| 产品仓库忽略 `data/` | 账本必须是用户选的共享目录，不要和数据库、Key 混合同步 |

### 1.5 为什么不租服务器、不用 GitHub

| 选项 | 结论 |
|---|---|
| 租一台云主机跑统一后端，licence 只放服务器 | 能「只查一次」，但这正是当前不愿做的事 |
| 把本机工作台绑 `0.0.0.0` 当服务器 | 等于把整套助手和钥匙暴露出去 |
| 独立 Git 仓库当运行时总线 | 即使用软件代 commit，仍要账号、令牌、分叉，四人都不会修 |
| **网盘共享文件夹 + 本机自动读写** | 不租主机；用户只会「加入文件夹、在工作台选一次」；重复查询用套餐换简单 |

文件布局（一档一个 JSON）保留。**白天运输是网盘共享文件夹。** GitHub 可以当可选的异地备份，由软件在后台或退出时自己 commit/push，对客不出现提交按钮；不能代替网盘当盘中总线，也不能只靠「关窗口那一下」当唯一同步。

### 1.6 明确拒绝的做法

| 做法 | 为何不做 |
|---|---|
| 租云主机 / 统一部署后端 / 云函数代打麦蕊 | 当前不愿承担的运维与费用；本文就是它的替代 |
| 另买一台常开电脑当行情网关 | 没有这笔计算资源 |
| 把工作台绑到 `0.0.0.0` 并带上 licence | 暴露整站和钥匙 |
| 用网盘同步整份 `data/` | `app.db` 互相覆盖；licence 可能进同步盘 |
| 让用户对源码库或账本点 commit/push | 四人不会 GitHub |
| 运行时依赖 GitHub | 凭证和分叉仍要人会修 |
| 为省次数做跨机锁、claim 文件、强制抖动、网盘未到就禁止打麦蕊 | 额度充裕；这些才是「麻烦」 |
| 把日线、财务、股东、成本按档写入共享盘 | 体积大，且那些数据可再向麦蕊要 |
| 工作台放「提交账本 / Push」按钮 | 等于承认用户要会版本管理 |

「一起贡献」在额度充裕时更直白：谁在线谁都可以拉行情；谁拉到了就尽量写进当前档；当前档缺某只代码，后来者可以**只补这些键，不改已经写下的价**。不要求全网互斥出唯一一次 HTTP。

## 2. 核心模型：两条路径，一个档案

### 2.1 现货 vs 胶带

| 路径 | 何时用 | 可否打麦蕊 | 失败时 |
|---|---|---|---|
| **现货（本机）** | 查询表、盯盘告警、用户点刷新、对话里要现价 | 可以。共享档没有、缺代码、或已过期，就拉 | 标明麦蕊失败；不要假数 |
| **胶带（共享文件夹）** | 回放某一档、时段折线、Agent 的 `clock_series`、尽量让四人看到同一个 `as_of` | 不在分析时再打；只读已经落盘的 JSON | 缺档就是空洞，不插值 |

现货可以比胶带新几秒或重复打几次，这是接受冗余的含义。胶带一旦某只股票的价写进某一档，**不要改这只的数字**（分析要稳定）。可以往同一档里**追加**当时还没有的代码。

### 2.2 两种数据集

| 数据集 | 粒度 | 从哪来 | 事后还能向麦蕊要吗 |
|---|---|---|---|
| 墙钟胶带 | 先 5 分钟一档的现价横切面 | 各机现货成功后尽量写入 `CLOCK_DIR` | **不能**（这是文件夹存在的理由） |
| 日线 / 名单 / 财务 / 股东 | 日或更慢 | 麦蕊 + 本机 `data/cache` | 能 |

5 分钟档不是 5 分钟 K 线。能画折线，不能把相邻点编成蜡烛。麦蕊现价里若已有开高低或成交量，原样多记，不编造。

### 2.3 墙钟切档（上海时区）

- 时区 `Asia/Shanghai`。第一期 `interval_sec = 300`。
- 档位向下取整。**10:08 的当前档仍是 10:05。**
- 工作日 09:00–15:00 检查是否该写档。收盘后不新开现价档。20:20 复盘用日线，不用盘中最后一档冒充次日。
- 改 1 分钟只改间隔；不要同一天两种间隔两套真相。

界面上的「现在这张表」应标明用的 `as_of`：若来自共享档就用档内时间；若来自本机刚打的麦蕊、而共享档还没有，也按当前墙钟档标记，并在写档成功后与档案对齐。不要用「我点刷新的时钟」当分析时间轴。

### 2.4 10:05 / 10:08（接受冗余之后）

1. 10:05 A 发现文件夹里没有 `1005.json`（或没有自己要的代码）→ 打麦蕊 → 写档。
2. 10:08 B 若已经同步到这份文件且代码齐全 → **用文件，不必再打**。这是省事，不是纪律。
3. 10:08 B 若网盘还没到 → **B 自己打麦蕊，界面照常刷新**，再尝试写 `1005.json`。若 A 的文件随后到了：规范名已存在则 B 不再覆盖已有代码；缺的代码可以补进去。
4. 界面不要为了等网盘卡住。也不要为了「只许 A 打」让 B 干等到 10:10。

两台在 10:05 同时打麦蕊：可以。先写上规范名的人留下这些代码的价；后到的人读文件，缺则补，已有则沿用。

## 3. 对客怎么接上账本（零 GitHub、零服务器）

### 3.1 产品仓库与账本分开

- 源码仓库继续忽略 `data/`、`.env`。开发者自己 git；四位使用者不必碰 GitHub。
- 账本是用户在工作台选的一个文件夹 `CLOCK_DIR`，推荐建在坚果云 / OneDrive 等已在用的同步盘里，例如 `股市助手-墙钟账本`，用网盘「共享」请另外三人加入。
- 不要选软件安装目录，不要选整个 `data/`。
- 未选 `CLOCK_DIR`：本机照常打麦蕊、本机缓存，工作台标明「墙钟档案未启用」。单人指到 `data/clock/` 也可以，只是没有共享，自己仍能留下胶带。

软件在目录下自动创建 `quotes/`、`universe/`。没有提交按钮。工作台只显示：是否已选目录、最后一档 `as_of`、能否写入。

### 3.2 同步谁来做

网盘客户端。助手只读写本地目录，不实现同步协议，不租对象存储。

各机需要网盘处于登录同步；这是「文件夹在转」，说明书写一句即可。网盘未同步时现货仍可打麦蕊，档案稍后补上。

### 3.3 Git 远程：可选备份，可以自动提交，但不能只放在关闭脚本里

可以。若 `CLOCK_DIR` 本身是一个已经 `git remote` 好的目录，软件完全可以在**不打扰用户**的情况下 `commit` 并 `push`，四人不必会 GitHub 网页、不必会命令行。这解决的是「持久化到远程多一份」，不是「关掉才开始共享」。

**关闭时再提交，作为最后一次冲刷是对的；作为唯一同步是错的。**

| 时机 | 该不该 git push | 原因 |
|---|---|---|
| 写完一档 JSON 之后（或每过几档合并一次） | **应当**（有远程才做，失败只记日志） | 别人和异地备份在盘中就能拉到，不必等你下班 |
| 进程正常退出（Ctrl+C，启动脚本 `finally`） | **应当再冲一次**，短超时（建议 ≤10 秒），失败不挡退出 | 把尚未 push 的文件带走；用户无感知 |
| 点窗口右上角、注销、直接断电 | **不要指望** | 见下 |

白天的档案仍然先写到本地/`CLOCK_DIR` 文件。Git 只是把**已经落盘的 JSON** 送到远程。不需要在内存里攒一天、关机再序列化。

#### 为什么不能只写在「关闭脚本」里

C6 之前，`scripts/run-server.ps1` 为了避免关窗口留下 python 僵尸，在点叉、注销、关机时会立刻 `taskkill` 子进程；Windows 给控制台关窗的时间往往只有数秒。`git push` 到 GitHub 经常比这更慢，一旦超时，窗口被系统杀掉，远程什么也没有。强制结束 python 时，FastAPI `lifespan` 的 shutdown **也跑不到**。

现在关窗口不再杀进程（C6），但关窗处理函数里仍然**死等 GitHub 不行**：系统可能很快拆掉控制台。Git 仍以写档后异步 + Ctrl+C `finally` 为主。

因此（C6/C7 已按此落地）：

1. **关黑窗口不杀 python**：服务以隐藏进程启动，不加入 `KILL_ON_JOB_CLOSE`；CTRL_CLOSE 只让启动脚本退出。托盘在 python 进程里（`src/platform/tray.py`），点「退出助手」才停 uvicorn。
2. **冲刷放在启动脚本的 `finally`（Python 停掉之后也可以）**，因为文件已经在磁盘上，不依赖还活着的 uvicorn。Ctrl+C 走这条路，成功率高。点叉那条路**不等 git**。
3. **盘中另有一次尽早 push**（写档后异步、超时丢掉），这样即使晚上直接叉掉窗口，白天的档多半已经在远程。
4. 超时、无凭证、网络失败：只记 `data/logs/clock-git.log` 与 `data/clock_git_status.json`，下次启动再试一次。不要弹 Git 错误框，不要让助手起不来。对客只说：「档案还没备份到远程，下次打开会再试」。

#### 和网盘怎么分工

- **网盘**：四人白天互相看见档案的主路径，不会用 GitHub 也能用。
- **Git 远程**：多一份不在网盘账号上的历史（换电脑、网盘文件夹被删时还能 clone）。由会建私有库的人建好远程、在本机登录一次 Git 凭证；其它人可以不配 git，只靠网盘。
- 禁止把源码仓库和账本仓库混成一次 push。禁止把 `.env`、licence 加进这次提交。只 `add` `quotes/` 与 `universe/`。
- 对客界面仍然没有「提交 / Push」。有远程且最近一次 push 失败，本机数据页用一句人话：「档案还没备份到远程，下次打开会再试」，不要出现 rebase、rejected、PAT。

网盘是白天主路径。git 备份已按「写档后异步 push + 退出 finally 再冲一次」落地，**不要只改关闭脚本。**

## 4. 账本布局与文件契约

### 4.1 目录

```
<CLOCK_DIR>/
  quotes/YYYY-MM-DD/HHMM.json
  universe/<login>.json
```

最新档 = 规范名文件里 `as_of` 最大者。不维护众人抢写的 `latest.json`，也不按天追加一份 JSONL。

### 4.2 档口 JSON

```json
{
  "schema": 1,
  "as_of": "2026-09-20T10:05:00+08:00",
  "interval_sec": 300,
  "writers": ["hanish"],
  "codes": ["000001", "600038"],
  "quotes": {
    "000001": {
      "p": 11.20,
      "pc": 0.52,
      "pe": 5.1,
      "sjl": 0.6
    }
  }
}
```

| 字段 | 规定 |
|---|---|
| `schema` | 整数；不兼容才加一 |
| `as_of` | 档位起始，带 `+08:00` |
| `interval_sec` | 写入时的间隔 |
| `writers` | 曾向这一档追加过内容的节点，便于事后知道谁补过代码；不当权限。第一期若实现省事，写成单个 `writer` 也可以，读档时两种都认 |
| `codes` | 已有报价的代码，升序 |
| `quotes` | `code6` → 麦蕊已返回的标量。最少 `p/pc/pe/sjl`。有开高低或量则原样多记 |

已存在的 `quotes[code6]` **禁止覆盖**（包括用「更新的现价」去改 10:05 那一刀）。只能增加新的 `code6`。追加后把该节点写入 `writers`，重写 `codes`。

禁止把日线数组嵌进档口。

### 4.3 `universe/<login>.json`

```json
{
  "schema": 1,
  "login": "hanish",
  "updated_at": "2026-09-20T09:12:00+08:00",
  "codes": ["000001", "600038"]
}
```

- 每人只覆盖自己的文件。自选变化时由软件更新，不要每档都写。
- 写档或补档时：并集 = 所有 `universe/*.json` 的 codes ∪ 本机当前自选。并集是「尽量一次拉齐」，不是「不许只拉自己的」。本机也可以先拉自己需要的，再把缺的补进档——冗余可以。
- 并集硬顶仍在（与 `QUERY_SYNC_LIMIT` 同阶）：防止误把全市场写进 universe。超限则只拉本机自选并记日志。
- 成本、买区、持有逻辑不进此文件。

### 4.4 写入与冲突（从简，不为省次数）

1. 规范名 `HHMM.json`：没有则创建；有则只做「缺代码就追加」。
2. 写入过程：读入（若有）→ 合并新键 → 写到 `HHMM.json.<login>.tmp` → 替换规范名。网盘上两台同时替换，可能后写覆盖先写，或打出冲突副本——**可以接受**。读档时：
   - 规范名存在 → 以它为准；
   - 另有冲突副本 → 不画进折线第二遍；若规范名缺某代码而副本有，可以把缺的键补进规范名（仍不改已有键）。
3. 忽略 `*.tmp`、`desktop.ini`、`.DS_Store`。
4. 不要用 `*.lock` 做跨机锁。

分析 API 对同一 `as_of` 只输出一次。

## 5. 运行时协议（每台相同）

「对齐当前档」同时服务现货和胶带，**允许打麦蕊**。

```
slot = floor(now_shanghai, interval)
path = quotes/YYYY-MM-DD/HHMM.json
need = 本机这一刻要用的代码（自选 / 查询池 / 规则用到的）
file = 读规范名（没有则空）

若 file 覆盖 need 且 now 仍在这一档内:
    现货用 file
    不必打麦蕊（省事，不是强制）

否则:
    打麦蕊（quotes_many：need 里 file 还没有的；也可以整份 need 再拉一遍，冗余可接受）
    现货用「file 已有键 + 本次结果」；同一代码以 file 为准（档内不改价），file 没有的用本次
    尝试把本次新键写入 path（创建或追加）
    写失败 / 网盘只读: 现货仍然可用，档案这一次没落下，下一检查点再试
```

补充：

1. **启动探测**：有可用的最近档则不必为探测再打三枪；没有档时探测照打，次数可接受。
2. **网盘落后或没选 CLOCK_DIR**：现货直连麦蕊，工作台标明来源是本机。有目录则稍后补档。不再出现「账本未刷新因此禁止看价」。
3. **无 licence**：只能读已有档；现货空着并说明原因。
4. **并集里没有、用户点名立刻看的一只**：本机打这只（冗余可接受），标「本机即时」；同时写入自己的 universe，下一档并集更大。盯盘默认仍以规则用到的代码为准。
5. **`MAIRUI_OFFLINE=1` / 演示 licence**：不写共享档。可读已有实盘档。
6. **非交易时段**：不新写档。读上一交易日最后一档必须标明日期。

盯盘：现货按上面规则取价（可以刚打过麦蕊），命中记录带上所用 `as_of`。复盘次日 K 线仍用 `market.history`。

调度：

- 每分钟醒一次：对齐当前档（读文件；缺则拉；再尽量写）。
- 规则扫描仍可 5 分钟，只是吃对齐后的现货，不必另开一套 HTTP。更密的盯盘 = 更勤地走同一函数。
- 自选保存后更新 `universe/<login>.json`，不挡本机数据库。

`MarketClient` 仍是唯一对麦蕊发 HTTP 的模块。账本层只决定「现在要不要调它、调完写不写文件」。

## 6. 和本机 `data/` 的关系

| 路径 | 是否共享 | 说明 |
|---|---|---|
| `CLOCK_DIR` | 是 | 胶带 + universe |
| `data/cache/` | 否 | 日线、名单 |
| `data/app.db` | 否 | 自选、规则、告警、会话 |
| `data/artifacts/` | 否 | 导出 |
| `.env` | 否 | licence、模型 Key、`CLOCK_DIR` 路径 |

查询表：慢字段走本机缓存；现价走第 5 节对齐结果。本机数据页：选文件夹、显示最后一档、能否写。不提供删档，不提供 Git 按钮。

## 7. 时段分析、回放与绘图

只读胶带，分析过程不要为了画图再打一轮盘中价（日线另说）。

| 能力 | 输出 |
|---|---|
| `clock_slot(as_of)` | 那一刀 JSON；没有则空洞 |
| `clock_latest()` | 目录里最新规范档（可注明是否已过期） |
| `clock_series(code, start, end)` | `{as_of, p, ...}` 升序，缺档跳过、不插值、同一 as_of 一次 |
| `list_slots(date)` | 当天档列表 |

| 问题 | 用什么 |
|---|---|
| 现在什么价、盯盘响不响 | 第 5 节现货（文件优先，否则麦蕊） |
| 今天 10:05–14:00 怎么走 | `clock_series` 折线 |
| 上周二 10:05 当时全表 | `clock_slot` |
| 这周收盘离底 | 日线 + 底/顶 |
| 复盘次日同向 | 日线，见智能体运行时 |

前端：现价旁标明 `as_of` 和来源（档案 / 本机即时）。折线缺档留空。设置账本只说「选网盘里已共享的目录」。

Agent：只读 `clock_slot` / `clock_series`，禁止把全天 JSON 塞进提示词。引用必须带时间。

## 8. 后台挂机与退出冲刷

关黑窗口后进程留在托盘，盯盘和补档继续。彻底退出：托盘「退出助手」或启动窗口 Ctrl+C（此时再冲一次 git）。网盘客户端建议开机自启，否则别人写的档进不来——进不来时现货仍可自己打麦蕊。

四台全关：胶带停在上一档。这是不租常开服务器的上限。

告警只写本机数据库，不进共享文件夹。

若启用了 Git 远程备份：退出冲刷见第 3.3 节。启动脚本在 `finally` 里短超时 push 即可；不要为了等 GitHub 让「按任意键关闭本窗口」一直卡住。点叉路径现有逻辑是尽快杀掉 python，与「关机才第一次 push」不相容。

## 9. 安全

- 共享文件夹权限仅此四人，不要公开链接。
- licence、模型 Key、口令不出现在 JSON 和文件名里。
- 进程仍绑 `127.0.0.1`。
- 演示 / 离线夹具不写入共享档。
- 不引入云函数、GitHub Actions、租来的行情中转。

1 分钟一档若网盘太慢，可以以后加「局域网读最新档」——那是优化延迟，不是为了省次数；第一期不做。

## 10. 故障与降级

| 情况 | 行为 |
|---|---|
| 当前档覆盖 need | 用文件，可不打麦蕊 |
| 当前档缺 / 缺代码，有 licence | 打麦蕊；现货立刻可用；尽量创建或追加档案 |
| 写文件失败 | 现货仍可用；下轮再写 |
| 冲突副本 | 规范名优先；缺键可从副本补；折线不双计 |
| `CLOCK_DIR` 未选或不可写 | 纯本机麦蕊；标明无档案 |
| 无 licence | 只读已有档 |
| 并集超硬顶 | 退回本机自选，记日志 |
| sample-only / 离线 | 不写共享档 |
| 某档全天缺失 | 分析跳过，允许空洞 |

没有「请手动 rebase」对客状态。没有「未同步因此禁止刷新」。

## 11. 间隔从 5 分钟到约 1 分钟

5 分钟先跑通：选目录、写档、追加缺码、回放折线、网盘冲突副本不炸。

改 1 分钟：重复查询更多，**按前提可以**。网盘可能跟不上「别人刚写的文件」，于是多人各打各的——也可以。档案仍会陆续到齐。若以后觉得「看价」被网盘拖慢，再考虑局域网读最新档；不要因此去租服务器。

## 14. 明确不做（账本范围）

- 不租服务器、不上云函数代打麦蕊。
- 不把账本当通用库（财务、日线、对话、告警不进）。
- 不做跨机互斥锁。
- 不把空洞插值成假 K 线。
- 不荐股、不按档案自动改规则。
- 不同步 `app.db`。
- 第一期不上局域网端口。对客不操作 GitHub；可选的自动 push 不是对客功能。
- 不以「关闭时才第一次 git push」作为档案同步的唯一手段。

## 15. 已定倾向与仍可调的点

已定：

- 不租统一后端；四人本机取数；额度充裕，冗余查询可接受。
- 一档一文件；已有代码的价不改；允许追加缺码；先 5 分钟。
- 账本是用户选的网盘共享文件夹；软件自动读写；对客零 GitHub。
- Git 远程若启用：写档后尽快异步 push，退出再短超时冲刷一次；点叉不保证成功。
- 现货与胶带分开：看价可以打麦蕊；事后分析只认文件。
- 字段原样多记不编造；最少 `p/pc/pe/sjl`。

仍可微调：间隔秒数、并集硬顶、`writer` 单字段还是 `writers` 数组、单只「本机即时」开关默认是否关闭。

改「不租服务器 / 对客零 GitHub / 现货允许冗余 / 档内已有价不改」任一则先改本文，再改代码。
