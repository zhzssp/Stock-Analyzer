## 分工与权威

冲突时只认一处，另一处事后回写，避免两份「主设计」。

| 问题 | 权威 | 其它文档的角色 |
|---|---|---|
| 做不做、字段清单、接口路径、S0–S9 分期 | **软件设计文档** | 对客只写用户感知；实现后回写对客 |
| 麦蕊能不能取到、怎么拼 URL、演示 licence | **API现状** + 验证脚本 | 验证报告 / 指数成份探针是某次跑数快照 |
| 图 1 未闭环项是否因官方无源 | **problems/** 对应核实记录 | API现状是 2026-09-02 的 74 接口盘点，不含此后数据中心/公告 |
| 智能体如何拆、禁止超级 Agent、消息主题 | **设计文档**（专论） | 落地结构以软件设计文档为准 |
| 用户看见什么、不承诺什么 | **对客功能说明** | 不得擅自加「能用」而未实现的能力 |
| 决策卡 / 队列等是否开工 | **提效缺口评审**（待审） | 未勾选则不改代码、不改对客承诺 |
| 工作台长什么样、怎么点 | **frontend/** | 视觉说明在 `frontend/README.md` |

生成类文档（验证报告、指数成份探针）由脚本覆盖，**不要当设计稿编辑**。
