1. 按一条可落地的炒股思路，当前软件还缺什么。
2. 哪些功能真能帮股民少看、看对、记得住；哪些不该加。

## 1. 评审用的核心思路

最强、且和本产品定位一致的思路不是「再多几个指标」，而是：

**小池子里，把每只票变成一条可执行规则：为什么拿、区间在哪、什么变了必须看、看完记一笔。中间地带默认什么都不做。**

拆开是四条，缺一条软件就会把人带回「天天刷表」：

| 原则 | 含义 | 本软件该不该管 |
|---|---|---|
| 小池子 | 默认自选约几十只，不海选 | 已管，必须保住 |
| 规则化区间 | 每只有买区、减仓区、作废条件 | 只有统计底 / 默认目标卖价，没有「用户自己的规则」 |
| 变化检测 | 股东、事件、资金、价位区间变了才打断 | 已开四条规则；卖区提醒未做 |
| 复盘闭环 | 看过、做过、下周还记得 | 几乎没有 |

散户常见亏损来源（无纪律加仓、没有卖点、自选高度同质、同一条刺激第二天当新闻）都落在后三条，不落在「少看了微博」。

因此评审标准是：**这个功能会不会让「今天该加 / 该减 / 不该看」变得更便宜？** 只增加可看的数，不算提效。

## 2. 已经做对、评审时不要改掉的

| 已有 | 为什么要对 |
|---|---|
| 默认只盯自选，交易所/板块是另池 | 避免做成全市场选股器 |
| 离底%、长窗底、顶、目标卖价 | 回答「在自己的历史区间哪里」，比再堆均线有用 |
| 股东变动、资金偏离、分红/增发/解禁、接近底部 | 盯变化，不是盯静态 |
| 导出 Excel + `excel_diff` / `warehouse_get` | 历史表是记忆，不是一次性截图 |
| 未就绪 Tool 保持 `enabled: false` | 不编资讯、期货、政策 |
| 不做下单、不做荐股承诺 | 推送的是规则命中 |

架构上继续走「加字段 / 加 Tool / 加规则」，不要为本文另起一套核心循环。

## 4. 缺口（按对决策的妨碍程度）

### 4.1 表上有市场数，没有「你的规则」

每只票现在是一行公开数据：现价、财务、统计底、默认「底涨 50%」目标。

没有：

- 我为什么拿这只（一句话逻辑）
- 成本、股数、还能加多少
- 我的买区 / 减仓区（可覆盖默认统计值）
- 什么情况逻辑作废（跌破某价、股东大变、主业对不上）

后果：Agent 只能报数，不能问「这是否碰到你的规则」。接近底部有提醒，接近自己的减仓位没有，系统会训练成「跌了才看、涨了不处理」。

### 4.2 有提醒，没有「看完怎么处理」

命中写入 `alerts` 即结束。没有：已看 / 加仓 / 减仓 / 再观察 / 逻辑作废，也没有半句备注。

后果：同一类刺激第二天仍当新闻。监控越准，未处理队列越吵。

### 4.3 有快照，没有「今早一眼对照」

底层已有 `snapshots`、`excel_diff`、档案库。主路径仍是「再查一张表」。

股民每天要的是：相对上周导出或昨收，谁的价、股东、离底%、资金变了。这个能力差的是入口，不是算法。

### 4.4 有「接近底部」，没有行动队列

表是平铺的。区间中部的票和该处理的票抢眼神。researcher「看市场」目前更接近自选行情复读，不是「今日该看谁」。

### 4.5 事件是摘要，不是日历

分红 / 增发 / 解禁能回答「有过」，很难回答「未来 20 个交易日谁解禁、谁除权」。历史事件和未来风险不是同一件事。

### 4.6 没有相对强弱与池子相关度

有行业 / 概念列，没有「相对行业、相对某基准本周谁强谁弱」，也没有「7 只里 5 只军工」的警告。小池子一旦同质，所有规则会在同一天一起响。

### 4.7 对客列与决策列仍缺

对「小池子 + 区间规则」最有用、且尚未注册的列：

- 换手、市值：判断「接近底部」是缩量还是放量跌
- X 日价 / 比价差：相对用户记得的那天
- 近目标卖价：与 `near-bottom` 对称

激励 / 并购 / 减持、政策、期货、出口占比仍受数据源约束，保持插槽即可，不在本文当必做。

## 5. 建议能力（供勾选，不是开工令）

每条都写：**用户感知、依赖、验收、不做什么**。实现时仍走字段插件 / Tool / 监控规则，不改查询引擎主循环。

### P0 · 决策卡 + 成本仓位 + 近目标提醒

**用户感知：** 每只自选可填逻辑、成本、股数、买区、减仓区、作废条件。表上可见：相对成本、距买区、距减仓区。现价进入减仓区时提醒，与接近底部对称。

**依赖：** 新表（或扩展 `watchlist`）；目标价已有；监控加一条 `near-target`。

**验收：**

- 不填决策卡时，行为与现在一致（只用统计底 / 默认目标）。
- 填了成本后，相对成本列有数；Agent 问「该不该减」时先引用卡上的减仓区，不编建议收益率。
- `near-target` 可关；未填减仓区则回退到统计目标卖价。

**不做什么：** 不自动下单、不写「建议买入」。

### P1 · 提醒闭环 + 一键对照上一份 Excel

**用户感知：** 每条提醒必须点一种处理。查询页有「对照上一份档案」，变了的行置顶标色。

**依赖：** `alerts` 加状态；`excel_diff` 提到传统查询主路径。

**验收：**

- 未处理提醒在监控中心保持未读；处理后不再用同一 `idempotency_key` 刷同一句话。
- 有至少两份导出时，一键对照不经过对话窗口。
- 周视图能数「命中几条、处理几条」。

**不做什么：** 不做独立社区/分享。

### P2 · 「今日该看」队列

**用户感知：** 顶栏或监控页固定队列：靠近买区、靠近减仓区、未处理提醒、7 日内事件。其余标成「区间中部，默认不动」。researcher 输出同一队列，而不是自选行情复读。

**依赖：** P0 的区间；P1 的提醒状态；事件日历可先用已有分红/增发/解禁。

**验收：** 自选 10 只且仅 2 只命中规则时，队列长度约为 2，不把 10 只全铺开。

**不做什么：** 不按「AI 评分」排序。

### P3 · 自选事件日历

**用户感知：** 未来约 20 个交易日：解禁、增发、分红/除权。解禁/增发默认高于历史分红。

**依赖：** 现有 `corp_events`；需把「日期」从摘要里解析成可排序字段（数据脏则该行空，不编日期）。

**验收：** 点一只票能看到下一事件日；无日期则标明「有事件、无明确日」。

**不做什么：** 不接全市场财经快讯冒充日历。

### P4 · 相对强弱 + 行业集中度

**用户感知：** 两列：相对行业、相对基准（先用沪深 300 或用户指定的一只指数/ETF，S0 未证成份前可用点位序列，不成份列表）。侧栏：「国防军工 5/7」。再加同行业票时提示。

**依赖：** 行业列已有；基准行情（指数点位或替代标的）。

**验收：** 池子里同一 `industry` 超过阈值（建议 ≥40% 或 ≥4 只）有提示。相对强弱列缺数据时留空。

**不做什么：** 不把「深市全部」写成深证成指。

### P5 · 补列：换手、市值、X 日价

**用户感知：** 查询可选这些列；X 日价按用户存的日期取收盘（本地按日期过滤，不信任接口 `st/et` 在演示 licence 下的行为）。

**依赖：** [API现状](./API现状.md) 与验证报告；正式 licence 下复测历史深度。

**验收：** 与图 1 其它列一样可勾选、可导出、可被 Agent 引用。

**不做什么：** 不把 X 日价默认成全表必选。

### P6 · 带自选过滤的资讯 / 政策（最后）

**用户感知：** 仅当标题/正文命中自选名称、行业或决策卡关键词时提醒。未接数据源则保持未启用。

**依赖：** `web_finance_search` / `policy_news` 真源；P0 关键词可选。

**验收：** 无过滤的信息流不准上线。未启用时界面与现在一致。

**不做什么：** 不做全网热搜、不做「情绪评分荐股」。

## 6. 明确不建议加（提效负项）

| 不建议 | 原因 |
|---|---|
| 全市场选股器、题材排行 | 和「小池子」相反 |
| AI 荐股、目标收益、胜率承诺 | 已写进产品不做；与规则命中冲突 |
| MACD / KDJ / 一堆副图而没有「违反哪条规则」 | 增加注视，不增加决策 |
| 未过滤资讯流、未过滤微博 | 分心 |
| 接券商下单 | 本产品价值是少看、看对、记得住 |
| 为期货/出口占比先做假数 | 违反「未启用就不假装有数」 |

S9 Electron / 托盘仍按软件设计文档，与本文无关。
