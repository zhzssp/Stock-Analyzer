## 1. 评审用的核心思路

最强、且和本产品定位一致的思路不是「再多几个指标」，而是：

**小池子里，把每只票变成一条可执行规则：为什么拿、区间在哪、什么变了必须看、看完记一笔。中间地带默认什么都不做。**

拆开是四条，缺一条软件就会把人带回「天天刷表」：

| 原则 | 含义 | 本软件现在 |
|---|---|---|
| 小池子 | 默认自选约几十只，不海选 | **已管。** 自选是一等池；行情是指数成份，不是全市场选股器 |
| 规则化区间 | 每只有买区、减仓区、作废条件 | 只有统计底 / 默认「底再涨一半」目标卖价，没有用户自己的规则 |
| 变化检测 | 股东、事件、资金、价位区间变了才打断 | 已开五条规则（股东、基金持股、资金、分红/增发/解禁、接近底部）；卖区提醒未做 |
| 复盘闭环 | 看过、做过、下周还记得 | 几乎没有：提醒只写入，没有处理；对照表只在 Agent Tool 里 |

散户常见亏损来源（无纪律加仓、没有卖点、自选高度同质、同一条刺激第二天当新闻）都落在后三条，不落在「少看了微博」。

因此评审标准是：**这个功能会不会让「今天该加 / 该减 / 不该看」变得更便宜？** 只增加可看的数，不算提效。

## 4. 缺口（按对决策的妨碍程度）

下面只谈**有数也能做、且服务第 1 节思路**的缺口。无源项见第 6 节和第 7 节。

### 4.1 表上有市场数，没有「你的规则」

每只票现在是一行公开数据：现价、财务、统计底、默认「底涨 50%」目标。

`watchlist` 只有代码、名称、`group_name`。没有：

- 我为什么拿这只（一句话逻辑）
- 成本、股数、还能加多少
- 我的买区 / 减仓区（可覆盖默认统计值）
- 什么情况逻辑作废（跌破某价、股东大变、主业对不上）

后果：Agent 只能报数，不能问「这是否碰到你的规则」。接近底部有提醒，接近自己的减仓位没有，系统会训练成「跌了才看、涨了不处理」。

### 4.2 有提醒，没有「看完怎么处理」

命中写入 `alerts`（`title` / `detail` / 当日去重）即结束。没有：已看 / 加仓 / 减仓 / 再观察 / 逻辑作废，也没有半句备注。

后果：同一类刺激第二天仍当新闻。监控越准，未处理队列越吵。

### 4.3 有快照，没有「今早一眼对照」

工作台已有档案库和「对照上一份」Excel（走 `excel_diff`）。底层 `snapshots` 仍只给 watcher 做股东 / 资金差分，没有对用户开放的「今早对照」页。

股民每天要的是：相对上周导出或昨收，谁的价、股东、离底%、资金变了。Excel 对照已能看导出列；盘中快照对照仍差入口。

### 4.4 有「接近底部」，没有行动队列

表是平铺的。区间中部的票和该处理的票抢眼神。researcher「看市场」会带上最近 `watch.hit`，主体仍是自选行情 / 板块 / 资金复读，不是「今日该看谁」。

### 4.5 事件是摘要，不是日历

分红 / 增发 / 解禁能回答「有过」，也能在变动时提醒，很难回答「未来 20 个交易日谁解禁、谁除权」。历史事件和未来风险不是同一件事。

### 4.6 没有相对强弱与池子相关度

有行业 / 七大板块 / 申万 / 2026 概念列，没有「相对行业、相对某基准本周谁强谁弱」，也没有「7 只里 5 只军工」的警告。小池子一旦同质，所有规则会在同一天一起响。

基准不要用交易所全部冒充指数。行情侧已有成份切片，但查询引擎没有指数点位序列列；正式 沪深 300 成份仍未证实。

### 4.7 对「区间判断」仍缺的列

对「小池子 + 区间规则」最有用、且尚未注册的列：

- 换手、总市值 / 流通市值：判断「接近底部」是缩量还是放量跌（总股本、流通股本已有，市值不是同一列）
- X 日价 / 比价差：相对用户记得的那天（本地按日期过滤日线；不信任演示 licence 下接口 `st/et`）
- 近目标卖价（监控，不是新原始字段）：与 `near-bottom` 对称

激励 / 并购 / 减持回购起止、政策、期货价格、出口占比、个股每日北向仍受数据源约束，保持插槽或空列即可。

## 5. 建议能力（供勾选，不是开工令）

每条都写：**用户感知、依赖、验收、不做什么**。实现时仍走字段插件 / Tool / 监控规则，不改查询引擎主循环。

### P0 · 决策卡 + 成本仓位 + 近目标提醒

**用户感知：** 每只自选可填逻辑、成本、股数、买区、减仓区、作废条件。表上可见：相对成本、距买区、距减仓区。现价进入减仓区时提醒，与接近底部对称。分组若要做，只做自选 / 观察 / 备选三档，不当新数据源。

**依赖：** 扩展 `watchlist`（或旁表）；目标卖价列已有；监控加一条可关闭的 `near-target`。

**验收：**

- 不填决策卡时，行为与现在一致（只用统计底 / 默认目标）。
- 填了成本后，相对成本列有数；Agent 问「该不该减」时先引用卡上的减仓区，不编建议收益率。
- `near-target` 可关；未填减仓区则回退到统计目标卖价。

**不做什么：** 不自动下单、不写「建议买入」。

### P1 · 提醒闭环 + 一键对照上一份 Excel

**用户感知：** 每条提醒必须点一种处理。查询页有「对照上一份档案」，变了的行置顶标色。

**依赖：** `alerts` 加状态；Excel 对照已接到传统查询「对照上一份」/ 档案库（不必再发明对照算法）。提醒处理状态仍未做。

**验收：**

- 未处理提醒在监控中心保持未读；处理后当天不再用同一规则 + 同一代码刷同一句话。
- 有至少两份导出时，一键对照不经过对话窗口。
- 周视图能数「命中几条、处理几条」。

**不做什么：** 不做独立社区 / 分享。

### P2 · 「今日该看」队列

**用户感知：** 顶栏或监控页固定队列：靠近买区、靠近减仓区、未处理提醒、7 日内事件。其余标成「区间中部，默认不动」。researcher 输出同一队列，而不是自选行情复读。

**依赖：** P0 的区间；P1 的提醒状态；事件日历可先用已有分红 / 增发 / 解禁摘要。

**验收：** 自选 10 只且仅 2 只命中规则时，队列长度约为 2，不把 10 只全铺开。

**不做什么：** 不按「AI 评分」排序。

### P3 · 自选事件日历

**用户感知：** 未来约 20 个交易日：解禁、增发、分红 / 除权。解禁 / 增发默认高于历史分红。

**依赖：** 现有公司事件 Tool；需把「日期」从摘要里解析成可排序字段（数据脏则该行空，不编日期）。

**验收：** 点一只票能看到下一事件日；无日期则标明「有事件、无明确日」。

**不做什么：** 不接全市场财经快讯冒充日历。

### P4 · 相对强弱 + 行业集中度

**用户感知：** 两列：相对行业、相对基准。基准先用用户指定的一只指数 / ETF 的**点位序列**（不要成份列表冒充）。侧栏：「国防军工 5/7」。再加同行业票时提示。

**依赖：** 行业列已有；指数点位（`hsindex` 历史，正式 licence 下复测）。成份切片不能代替点位。

**验收：** 池子里同一行业超过阈值（建议 ≥40% 或 ≥4 只）有提示。相对强弱列缺数据时留空。

**不做什么：** 不把「深市全部」写成深证成指；不用离线成份切片假装是沪深 300 全名单。

### P5 · 补列：换手、市值、X 日价

**用户感知：** 查询可选这些列；X 日价按用户存的日期取收盘。

**依赖：** [API现状](../设计/API现状.md) 写换手 / 市值可从行情接口取；日线本地已有。正式 licence 下复测历史深度（见 [验证报告](../报告/验证报告.md) T0.5 / T3）。演示 licence 不得把样本写成指定日真实行情。

**验收：** 与图 1 其它列一样可勾选、可导出、可被 Agent 引用。空值留空。

**不做什么：** 不把 X 日价默认成全表必选；不把资金流向列填进北向。

### P6 · 带自选过滤的资讯 / 政策（最后）

**用户感知：** 仅当标题 / 正文命中自选名称、行业或决策卡关键词时提醒。未接数据源则保持未启用。

**依赖：** [P-20260915](../问题/P-20260915-麦蕊数据源缺口.md) 已确认公开接口无新闻 / 检索。要做必须先有第二数据源，再开 `web_finance_search` / `policy_news`。P0 关键词可选。

**验收：** 无过滤的信息流不准上线。未启用时界面与现在一致。

**不做什么：** 不做全网热搜、不做「情绪评分荐股」。
